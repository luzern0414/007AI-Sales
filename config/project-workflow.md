# 项目流程与资料管理

本机访问：http://127.0.0.1:8765。项目根目录由`PROJECTS_ROOT`设置，当前D:/Codes。项目只绑定一个项目目录，业务读取范围为docs。不会读取代码、依赖、构建目录；不移动或覆盖原始资料。

## 项目流程

客户洽谈 → 需求确认 → 方案提交 → 合同签订 → 开发启动 → 项目交付 → 验收通过 → 维护移交。

节点确认需实际发生时间和依据，保存确认人、修订和撤回记录。允许补录中间节点，但不会自动确认更早节点。概览突出最远已确认节点之后的环节；8个节点确认数量不代表工程百分比。签约后才允许在节点中填写计划交付，撤回签约会清除该日期。编辑项目只展示项目、客户名称。

## 标准docs结构

根目录保留 `README.md` 导航和 `项目进展.md`。根保留导航与项目进展；`01-商务与需求` 下按需设 `客户资料`、`方案文件`、`报价与合同`，`02-产品与开发` 下按需设 `设计文档`、`开发记录`，`03-测试与交付` 下按需设 `测试验收`、`交付资料`、`产品宣传`；图片集中放 `docs/素材/`。每个主目录最多三个分组，分组内直接存文件；不属于分组的文件留在对应主目录，不新增杂项或历史版本目录。不预建空模板，原目录说明仅为历史，当前路径以 `docs/README.md` 为准。 文件归类不代表项目节点已经完成。

目录生成器在 `server/docs_structure.py`，只创建三类文件夹和导航，不再批量生成空模板、空子目录或独立归档树。需要时再新增文件，历史版本直接在文件名注明日期、版本或“历史”。机器导出带 generated 标记，不重复分析；人工内容不覆盖。每场会议的纪要、原文和附件链接合并到一个文件，按已确认的业务节点归类；发生时间未知时仍明确标注未知。流程汇总、会议索引和变更记录放产品与开发，项目进展保留根目录。

2026-10-19已对12个编号项目执行一次性整理，路径、哈希及原文备份见本机 `output/docs-restructure-20261019/`。私有资料沿用Git忽略规则；依赖内部结构的演示资料包保留在各项目 `data/docs-originals/`，由商务与需求目录中的说明文件提供入口。正在被Office占用的文档保留原位。运行时自动同步只读资料，不自动搬动用户文件。

## AI上下文与持久化

概览AI分析支持保存项目背景、分析要求。输入包含原始文档、完整会议原文、历史摘要、节点确认/撤回和实际问题处理结果。正文按6000字符完整分片，保留每片检查点；原始输入哈希未变时复用检查点。每份来源归纳成一句话，项目总结一段话，风险引用必须逐字存在于该项目原文。未解析资料单独提示，不视为全部分析完成。

确认节点、资料同步、会议分析完成会重新排入项目分析；手动分析优先于批量资料。会议可以关联多个项目，各项目独立保存摘要。历史生成摘要用于承接，但不会单独触发再次分析。失败记录保留，AI异常最多自动尝试3次，也可从页面重新分析。

会议时间使用实际录制时间或人工填写值。导入录音未知时间显示待确认，不使用文件修改时间替代。文档按来源文件时间排列，并标注时间依据。同名新版录音保持一个会议，旧音频及对应原文/纪要作为历史版本保留，新音频重新转写。音频不进入文件列表、搜索或方案文档解析门禁。
