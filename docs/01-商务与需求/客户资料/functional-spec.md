# 手机 Web AI 销售助手功能方案

状态：**方案草案**。日期：2026-10-12，Asia/Shanghai。业务定位已明确，以下交互、范围和政策尚待评审及 PoC。

## 1. 产品解决的业务问题

软件公司售前经常在会后把录音整理成需求、向研发解释范围、等待原型，再带着静态页面与客户确认。信息易丢失，客户原话与销售推断混在一起，Demo 修改又容易与原需求脱节。
本产品把访谈证据、需求确认和业务演示连接起来。目标是让销售在手机上完成记录与确认，得到包含真实 API 和持久化数据的简单系统，用核心流程讨论方案是否正确。
Demo 服务于范围沟通与售前验证；正式生产交付、完整 CRM、合同报价和交付项目管理需另行规划。

| 使用者 | 主要需要 | 权限建议 |
|---|---|---|
| 销售/售前顾问 | 记录访谈、纠错、确认需求、生成和分享自己的 Demo。 | 本人负责项目及被明确协作授权的项目。 |
| 销售主管 | 查看组织进展、协助需求评审和分配负责人。 | 本组织监督范围，禁止跨组织访问。 |
| 组织管理员 | 管理邀请、成员、配额、保留政策和案例发布。 | 组织管理权限，敏感会话内容仍需必要授权。 |
| 客户访客 | 通过分享链接体验一个指定版本并反馈。 | 仅该 Demo 的演示功能；看不到平台、录音和需求全文。 |

试点使用邀请制组织账号。服务端从登录身份确定 tenant_id 和权限，客户端传参不能扩大可见范围。

## 2. 首期范围与关键边界

首期包括轻量客户/项目档案、前台录音与文件上传、粘贴谈话、录后异步转写、销售与 AI 聊天、需求确认版本、三模板生成、独立预览、限时私密分享、反馈及用量查询。
不把客户原话自动变成确认事实，不编造预算、联系人、成交概率或准确度小数；业务未知项允许保留未知。
首期不包含实时通话机器人、电话/微信系统音频采集、后台或锁屏录音、任意技术栈、自动生产上线、支付/短信/ERP 真连接。
实时字幕是后续候选，必须先证明它比会后需求和 Demo 更有价值。

建议演示范围控制为最多 3 个主要业务实体、5 个页面、1 条主流程；这是试点范围政策，尚未证明该限制能保证成功。
功能优先级采用 Must / Should / Could；只有被选入 Demo 的子集进入生成范围，其余需求保留在项目中。

## 3. 四个底部入口

| 页面 | 主要区域 | 主操作 | 空状态 |
|---|---|---|---|
| 首页 | 数据摘要、开始录音、最近会话、待确认需求、生成任务、到期跟进。 | 开始录音/继续处理。 | 显示 0 与“创建首个项目”，不造样例业绩。 |
| Demo 广场 | 平台模板、本组织私有案例、行业/流程筛选。 | 使用模板/查看范围。 | 没有私有案例时引导使用平台模板。 |
| 生成 Demo | 项目选择、确认需求、模板与范围、任务列表、结果。 | 确认并生成/查看 Demo。 | 从访谈创建需求或用合成需求试用模板。 |
| 我的 | 个人项目与 Demo、组织与权限、用量、录音/存储设置。 | 管理、导出、撤销、删除。 | 显示实际账号和配额状态。 |

手机布局优先卡片、列表、详情和表单，底部主动作保持可触达。复杂表格提供关键字段卡片或横向查看，不以桌面代码编辑器为主要界面。
返回页面须保留当前项目和服务端任务状态；录音中的页面切换需明确保存状态，不让底部导航悄悄结束采集。

## 4. 首页数据定义

默认时间范围建议为本月，允许切换；所有统计按当前权限过滤，时间使用组织时区，试点为 Asia/Shanghai。

| 指标 | 统计口径 | 不计入的对象 |
|---|---|---|
| 有效访谈数 | 区间内完成音频校验或已保存文本来源的 distinct conversation_id。 | 未保存草稿、重复上传、已删除会话。 |
| 待确认需求 | 本人范围内当前 draft 且已有需求条目的项目数。 | 历史 draft、superseded、纯空草稿。 |
| 已确认需求版本 | 区间内 confirmed_at 的 distinct requirement_version。 | AI 总结草稿；不能等同于客户签约。 |
| 生成成功数 | 区间内 succeeded 的 distinct generation_job。 | 修复轮数、重复消息、手动重试 attempt。 |
| 可访问 Demo | 当前有效 revision 且 runtime 可运行或可唤醒的数量。 | expired/deleted 产物，不推断成交。 |
| 待跟进事项 | 到期未完成的人工跟进记录。 | AI 推测客户承诺的日期，需销售确认后才建立。 |

近期任务显示真实阶段与更新时间。任务耗时来自服务器事件，页面不展示虚构百分比或模型自报的剩余秒数。
若未来统计“会话到需求”“需求到 Demo”转化率，需公布分母、观察窗口和去重口径；它们不叫成交率。成交状态只有人工确认及来源登记后才能引入。

## 5. 轻量客户与项目

客户只保存称呼、行业、组织和必要备注；联系人电话/邮箱可选且不进入默认 Agent 输入。
一个客户可关联多个项目，一个项目可关联多次会话、需求版本和 Demo。销售是项目负责人，主管可在组织内授权协作。
项目包含目标、当前阶段、负责人、下一步、跟进时间及关联资料；不扩展到完整 CRM 的财务、合同和邮件自动化。
未选客户时可先建立“未归档访谈”，保存后关联项目；跨组织移动、复制客户原始材料不开放。

验收：新建项目、重命名、归档及查询必须由真实记录驱动；组织 A 的客户/项目在组织 B 的搜索和接口中不可见。

## 6. 录音、上传与文本输入

### 开始录音

首页“开始录音”进入客户/项目选择页，展示录音、AI 转写与需求整理用途，销售登记参与者已知情的方式与说明版本，再申请浏览器麦克风权限。
权限拒绝、没有设备、设备被占用、非 HTTPS 分别给出操作提示；提供上传音频与粘贴谈话的替代入口。
支持范围先限定经测试的前台 Safari/Android Chrome；微信为独立 PoC 候选。录音页持续提示保持前台，不承诺锁屏、后台、电话或其他 App 的音频。

### 录音中的信息

显示实际经过时间、采集状态、待上传分片数量、网络状态，以及暂停、继续、停止并保存。暂停期间不算有效音频，经过时间与解码时长分别记录。
暂定单次最长 30 分钟、源文件总大小 100 MiB、分片目标周期 5 秒；它们是可调整试点政策，实际 dataavailable 周期会变化。
分片保存后上传并获得服务端确认，未确认内容在有界 IndexedDB 缓冲中等待重试。缓存受浏览器回收/配额约束，不能保证恢复。
切后台、来电、track ended 或页面重启后，显示已保存的部分及缺失提示；继续录音建立新 recording_stream_id。未发出的尾片可能丢失，不显示“已完整保存”。

### 停止与完成

停止后进入“保存中”，等待最后 dataavailable、stop 事件及全部上传确认；只有服务端检查顺序、缺片、hash、大小及解码通过，才能进入转写。
多个流分别合并解码，再按会话顺序组合；不把每个 Blob 当成可独立播放的音频。
不完整但可解码的部分允许销售明确选择“保存不完整访谈”，系统保留缺失标记，相关需求不得隐藏来源缺陷；不可解码时提供重新上传完整文件。
文件上传执行相同格式、大小、音频时长与恶意文件检查。粘贴谈话保留为文本来源，要求销售标注来源和角色，不假装它有音频时间戳。

验收：重复分片不重复存储，缺片 finalize 失败可补传；最后一片未确认时不能显示转写已开始。失败保留可用内容，不自动抹除会话。

## 7. 转写、角色与销售校对

录后异步 ASR 显示 queued / transcribing / ready / failed。页面关闭不会取消服务端任务；重新打开可查业务任务状态。
结果分句展示文本、匿名 speaker ID、时间范围和回听入口。speaker_0 先显示“说话人 0”，销售映射为“我/客户 A/未知”，该映射只对当前会话版本有效。
销售重点核对否定、金额、数量、日期、行业词和角色。修改建立新的 transcript_version，原版不可被静默覆盖，旧需求仍引用旧版本。
转写完成后由平台持久保存厂商原始结果与标准化片段；不长期依赖厂商短期下载 URL。
原音暂定 30 天后清理，转写全文 180 天。原音过期时保留可用文字并显示“原音已到期，无法回听”，不伪造回听链接。

验收：片段能定位到实际来源版本；人工纠错不会改变已有 frozen requirement 的证据；ASR 失败可重试且展示重试用量。

## 8. 与 AI 聊天并生成需求草稿

销售在会话页问“客户主要痛点是什么”“只演示维修工单可否”“需要再问哪些问题”，AI 使用选定会话/笔记提供有证据的回答。
客户原话、销售补充和 AI 推断用不同标签。销售输入“经理审批”是销售补充，不自动标为客户原话；AI 给出的“建议加看板”属于推断。
需求分析在服务端异步执行，输入固定 transcript/chat 来源版本。结果先经过字段、引用、实体关系、优先级和范围校验，再成为 draft。

| 需求组 | 展示内容 |
|---|---|
| 业务目标与痛点 | 想解决什么、当前流程哪里慢、有何依据。 |
| 用户角色 | 谁操作、谁查看、谁审批；未知身份保留未知。 |
| 数据与流程 | 实体、字段、关系、核心步骤、状态和规则。 |
| 功能优先级 | Must / Should / Could，逐条来源和验收行为。 |
| 约束与集成 | 设备、语言、敏感数据、外部系统及当前限制。 |
| 验收与范围 | 如何证明需求成立、拟演示和排除的功能。 |
| 澄清问题 | 冲突、未知、阻塞 Demo 的问题与可采用默认的假设。 |

每条需求分别保存 source_kind（customer_quote / sales_note / ai_suggestion / customer_feedback）、epistemic_status（fact / inference / unknown）和 confirmation（pending / accepted / edited / rejected）。销售明确补充可以是 fact，但不冒充客户事实；来源类型、认知状态和确认状态不混用。
每条需求展示引用片段或消息。AI 输出格式正确不代表内容真实，销售可接受、编辑或拒绝建议。
不要求补齐所有未知才允许生成；只阻塞会改变所选 Demo 核心行为的歧义。例如审批人数量是审批模板的关键问题，ERP 接口规范未提供则明确排除真实 ERP 集成。
分析拒绝、超长、坏结构或服务故障时，保留原会话并给出缩小输入/稍后重试的操作，不把未校验内容显示为已确认需求。

## 9. 销售确认与需求冻结

确认页集中展示目标、实体、流程、拟用模板、范围内功能、默认假设、模拟功能、排除项和阻塞问题。关键矛盾未解决时禁止确认所选 Demo 范围。
“确认需求”必须由当前登录销售操作；服务端写 confirmed_by、confirmed_at、requirement_version 和 canonical_hash。
confirmed 版本不可编辑。后续聊天、反馈或转写更正产生新 draft，重新确认后旧版成为 superseded；历史生成仍指向原版，不被新版本替换。
确认的是业务范围，不授权 Agent 访问真实客户账号、生产库或新增网络出口。
验收：双设备确认旧 revision 时返回冲突提示；运行中的 job 的输入 hash 永不变化，旧 Demo 显示“基于需求 v1，当前 v2 已确认”。

## 10. 生成 Demo 的交互

“生成 Demo”选项目 → 选 confirmed 需求 → 选择 CRM-lite/工单/简单审批 → 勾选演示子集 → 审阅范围与默认合成数据 → 提交。
范围摘要显示最多 3 主要实体、5 页面、1 主流程的建议上限，超范围引导缩减或交给研发，不偷偷改成静态假后端。
提交建立 durable generation_job；网络重试使用同一请求标识返回同一 job。明确点击“再生成一个版本”才创建新 job/revision。
默认每用户同时 1 个、租户同时 2 个生成任务；超配额显示排队或被拒原因，不后台无限启动。

| 任务阶段 | 手机显示 | 后续操作 |
|---|---|---|
| queued | 已排队、提交时间。 | 取消请求。 |
| planning | 整理实现范围。 | 查看 frozen 范围。 |
| generating | 生成页面与真实 API。 | 查看安全摘要。 |
| validating | 验证构建、API 和手机流程。 | 等待检查结果。 |
| repairing | 根据失败项修复。 | 显示第几轮，自动最多 2 轮。 |
| starting | 启动独立预览。 | 等待健康检查。 |
| succeeded | 验证通过，可演示。 | 预览、分享、导出、重置。 |
| failed / timed_out | 失败阶段与可读原因。 | 缩小范围或手动重试。 |
| cancelled | 已确认停止执行。 | 查看保留的阶段记录。 |

暂定每 attempt 从首次 lease acquisition 起活动执行上限 15 分钟，排队不计入，恢复不重置截止；人工 retry 建立新 attempt，但 job/租户累计预算仍生效。这不是生成时延承诺。cancel_requested 显示“正在停止”，supervisor 确认清理后才显示 cancelled。
自动修复属于同一 attempt；人工重试建立该 job 的新 attempt，独立统计模型/费用并保留历史。修改范围必须新需求确认后新建 job。
进度不展示原始思维链、敏感工具输出、主机路径或密钥。未过验证的产物不能分享或发布案例。

## 11. 预览、分享和反馈

预览默认打开独立页面，页面注明样例数据、已实现流程和模拟集成。前后端同一 Demo origin，销售无需理解内部端口。
列表、创建、读取、编辑、删除、筛选和简单状态转换走实际 FastAPI + SQLite；刷新及后端重启后仍可读取写入结果。
暂定 30 分钟无访问后 runtime sleeping；再次访问可从源码/数据库快照唤醒并检查健康。唤醒不改变历史 job succeeded，也不延长分享有效期。
销售创建私密分享，建议 7 天；实际有效期取组织政策、请求时长与产物剩余寿命的最小值，可立即撤销。客户 bearer 链接只访问指定 demo_revision 业务端口，不能进入平台、录音、数据库控制台或 terminal。
敏感客户原话、联系人和原始录音永不出现在预览。默认只使用合成数据；分享授权可演示 CRUD，但没有管理、导出、删除项目权限。
MVP 同一 revision 的销售和多个分享访客使用同一组合成 SQLite 数据，页面告知“多人演示共享数据”；项目 owner 可重置 seed，重置前提示会丢弃本轮演示修改。每客户独立数据副本是后续增强，不在首期承诺。
客户可提交文本反馈，标为“客户反馈”及时间；反馈仅形成变更 draft，由销售确认并生成新 revision，不直接改运行中的 Demo。
源码与 SQLite 快照暂定保留 30 天；到期显示 expired 及不可恢复资产清单。销售在到期前可导出脱敏源码，正式交付需新的安全和部署评审。

## 12. Demo 广场的隐私与复用

平台策划的合成模板全局可见。本组织案例默认 tenant-private，其他组织不可检索、访问图片或复用其来源。
客户派生案例进入公共展示需要所有者/管理员明确发布动作、脱敏检查和范围确认；首期可先关闭公共案例发布，只保留模板目录。
复用复制清洗后的 schema、样例数据和模板描述，创建新项目/Demo；不复制原会话、音频、真实客户信息、旧分享 token 或数据库快照。
撤销发布后目录和静态资源立即逻辑失效，物理缓存清理异步进行。截图也要替换真实名称、电话、金额和 URL。

## 13. 我的、删除与设置

“我的”列出本人项目、需求版本和 Demo；组织页面展示成员权限、可用模板、配额与预算。销售不能修改组织级地域和保留政策。
用量按 ASR 分钟、模型输入/输出 token、全部 retries、沙箱活动分钟及存储/流量显示；usage 未获取显示未知/估算，不能当作零。
删除项目先撤销会话/需求/Demo/分享访问并阻止新任务，随后取消执行和异步删除对象、副本及索引。删除进度可查询，不能将逻辑删除描述为所有备份已清空。
备份建议滚动 30 天且隔离不可在线访问；恢复备份先重放删除清单，最迟在备份窗口结束物理移除。此备份政策需要组织确认。
确认需求和引用摘录按项目目的保留到项目删除；原音/全文过期不自动删除已确认证据摘录，页面明确区分。组织也可选择更短的项目证据保留政策。

## 14. 关键异常与可验收行为

| 异常 | 必须呈现的结果 |
|---|---|
| 录音权限拒绝/硬件失败 | 原因和设置引导，上传/文本入口可用。 |
| 弱网/大 Blob/本地空间不足 | 采集与上传分开显示，缓存上限前提示停止保存；不能承诺尾部无损。 |
| 来源残缺/转写错误 | 可校对、重传、部分保存标记，需求保留证据质量提示。 |
| 模型拒绝/截断/Schema 无效 | 分析未完成，不产生 confirmed；重试有预算边界。 |
| 范围冲突/需求版本过旧 | 高亮冲突与当前版本，不覆盖新修改。 |
| 构建/CRUD/持久化失败 | 未成功，保留失败摘要，修复上限到达停止。 |
| 取消/worker 崩溃/重复投递 | 清理及恢复有状态，不能双份发布同一 revision。 |
| 分享到期/撤销/其他组织访问 | 拒绝访问，不泄露客户姓名或项目存在性。 |
| runtime 休眠/快照丢失 | 唤醒中或明确无法恢复，不能用旧链接显示空系统。 |
| 超预算/供应商限流 | 保留输入与阶段记录，暂停新工作并给出可读原因。 |

## 15. 虚构案例：售前把维修访谈变成工单演示

以下为虚构、去标识样例，不来自真实客户，也不代表已成功生成。
访谈片段 S12，02:10–02:25，客户角色经销售映射：“门店设备报修都发群里，经常漏掉。想让前台登记报修，再由值班主管分给工程师。”
片段 S13，03:00–03:12：“修完先给主管确认。短信以后再说，先看流程能不能跑。”销售消息 M8：“本次只演示单组织、一个主管，不做微信登录。”

| 候选需求 | 认知状态与证据 | 确认处理 |
|---|---|---|
| 前台登记设备故障并追踪处理 | fact，S12。 | 纳入 Must。 |
| 主管派单，工程师提交处理结果，主管确认完成 | fact，S12/S13。 | 确认一条主流程。 |
| 按状态筛选工单 | inference，由漏单痛点推导。 | 销售接受为演示假设。 |
| 手机号/短信对接 | unknown；S13 明确暂缓。 | 本次 out_of_scope，不填造接口。 |
| 单主管及演示角色切换 | fact，source_kind=sales_note，M8。 | 明确是销售补充的演示简化，不冒充客户原话。 |

冻结 v1 后，选择工单模板，主要实体为设备、工单、处理记录，页面为概览、工单列表、工单详情、报修表单、设备列表。
演示流程是新建 → 已分派 → 处理中 → 待确认 → 已完成；拒绝确认回处理中，不能随意跳到已完成。
实际验收动作：用合成设备“测试冷柜 A”创建工单，列表读到新记录，主管分派，工程师提交结果，主管确认；修改故障描述刷新后仍存在，重启后仍存在，删除另一条测试工单后再读返回不存在。
客户分享只展示这组业务行为。客户反馈“有两个主管要分级审批”形成新 draft；销售明确新范围，再冻结 v2 和生成 revision 2，revision 1 保留原证据和版本标签。
