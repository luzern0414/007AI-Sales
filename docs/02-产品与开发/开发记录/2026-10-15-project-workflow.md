# 项目流程与可视化概览

## 设计

以「洽谈、需求确认、方案提交、合同签订、开发启动、交付、验收、维护移交」八个固定节点组织项目。每个节点独立确认，保留实际时间、确认人、依据及撤回记录，不自动补全前序节点。顶部展示已确认节点数和最新已确认节点之后的待推进环节，较早未确认节点仍保留待确认状态，不将其称为开发完成率。只有合同签订及之后节点允许填写计划交付日期。

手机页面采用低饱和蓝灰、较大标题、流程卡片、统计卡片和简短时间轴。概览只显示一句摘要及一条后续建议；每份文件用一句话交代作用与新增信息。节点、会议、文档、风险分别呈现。项目编辑仅保留项目名和客户名。产品库直接显示产品卡片及新增入口。

## 数据与分析

- 新增节点确认表、项目分析状态表、录音关联表；迁移保留全部现有业务数据。
- AI分析支持补充背景与本次要求，持久保存。分析读取当前有效文档全文、会议原文、历次摘要、人工节点、问题及项目背景；大材料分片逐段覆盖，风险必须有真实来源和逐字证据。
- 文档新增、会议分析完成及人工节点变动入队项目分析；指纹与版本检查阻止过时结果覆盖新状态，失败保留旧结果并可重试。
- 录音保留原始存储，通过独立关联进入会议，文件列表排除音频。导入文件修改时间不能冒充会议实际发生时间。
- docs 按给定结构补齐缺失目录与文件，保留原件和已有README。机器维护导航与状态导出标识所有权并排除自我采集。全局项目发现统一绑定各项目docs。

## 实施与验收

1. 编写节点确认、权限、日期限制、重新分析上下文、风险证据、录音分离、目录幂等测试并验证失败。
2. 实现模型、迁移、路由、分析队列和无损目录导航。
3. 改造概览、节点、风险、项目编辑、产品库及工作台，移除名称纠错入口和接口。
4. 运行后端、前端测试及构建，隔离环境操作节点确认/撤回/AI分析/产品上传/文档下载；检查320px与390px手机页面。
5. 备份数据库，确认无正在录音后迁移部署，检查现有账号数据及运行服务，记录真实验收结果与限制。
