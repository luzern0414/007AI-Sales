## 证据与方案分层

已明确的业务定位是软件公司售前及手机 Web 四个底部入口。浏览器规范、官方 SDK 能力、许可证、项目维护声明属于已核查公开事实，不等于本项目已完成集成。
平台技术栈、三模板、单 worker、配额、保留期及模板范围上限属于建议。它们需要评审并通过 PoC 后才能变为实施基线。
ASR 准确度、手机浏览器最小版本、微信录音、国内托管沙箱网络、Celery/Valkey 兼容、生成质量及成本没有实测结论。

三份原始笔记：[录音与 ASR](<../%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3/audio-and-asr.md>)、[需求与 Agent](<../%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3/requirements-and-agents.md>)、[生成与运行](<../%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3/demo-generation-and-runtime.md>)。综合报告重新组织判断，未改写笔记。

## 评审责任与需收敛的选择

| 决策 | 建议负责人 | 验证活动与决定依据 |
|---|---|---|
| 第一优先业务模板 | 产品负责人 + 售前代表 | 用三种真实脱敏需求验证实体、流程和演示价值，选择最常见的一类先做。 |
| 部署地域及模型/ASR | 技术负责人 + 数据责任人 | 企业账号可用性、同语料评测、提供方数据协议、网络和实际账单。 |
| 预算与资源配额 | 业务负责人 + 运维 | 样本成本分布、峰值并发、15 分钟 attempt 执行上限和 2 GiB 容量实验。 |
| 录音/转写/证据保留 | 数据责任人 + 产品 + 运维 | 客户授权文本、项目存续目的、删除与备份恢复演练。 |
| 外部分享隔离 | 技术负责人 + 安全负责人 | 独立 runner 与强隔离 PoC、跨租户/预览 token/网络边界检查。 |
| 团队技术栈偏好 | 研发负责人 | 团队 React/Vue/Python/Node 经验、部署能力和两套栈维护成本。 |

需求与业务范围由销售确认，技术执行权限由服务器策略决定；销售确认不授予 Agent 新工具或生产系统访问权。
评审修改应同步更新功能、架构、数据、配置和模板文档，并记录版本依据；不得只改一个文件形成矛盾政策。

## 统一术语

requirement_version 指可冻结的需求版本；demo_revision 指一次可追溯生成产物；generation_job 指一次生成请求；attempt 指该请求的一次执行尝试。
job 的 succeeded 表示曾通过验证；runtime 的 running/sleeping/expired 描述当前能否访问，两者不互相覆盖。cancel_requested 是请求标志，不代表任务已停止。
事实、销售补充、AI 建议分别标记；匿名 speaker ID 只有人工映射后才展示会话内角色。
