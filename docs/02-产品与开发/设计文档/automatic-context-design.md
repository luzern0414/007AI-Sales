# 自动记录与项目承接设计

日期：2026-10-15。遵守开发规范与方案格式规范；沿用既有手机Web、独立录音归档、私有文档与项目权限。用户已授权持续实现、导入D:\Codes数字项目目录、使用本机密钥及优化原会议纪要。

## 业务流程

首页仅显示“开始录音记录”主操作。点击即可创建本人录音并开始采集，不要求选择项目、主题或日期。名称暂用录音开始时间，结束后依据原文自动命名，可随时修改。会议独立归属用户，允许暂未归类或同时关联多个项目，不复制原音或覆盖原文。

资料自动发现范围是D:\Codes下一层数字加名称目录；只有docs中的业务资料参与分析。无docs的目录也登记项目，随后可自动建立docs。代码、可执行文件、依赖目录、压缩包和机器维护的项目进展文件不作为模型背景。未读取内容的文件不得标为已分析。新项目可绑定既有目录或建立新目录；创建及写入都限制在配置根目录内，不跟随越界链接。

项目“时间线”改为“概览”：一段简短摘要说明上次做到哪里、本次变化、下一步建议；其下按时间显示文件及会议的简短进展记录，保留来源。文件修改时间仅作排序依据，另存导入时间，不能据此编造会议日期或完成日期。新发现的历史资料进入相应时间位置。

## 上下文与证据

解析器提取文档全部可读内容，长文按确定边界分块；每块保存来源ID、哈希、页码/原文定位。文件分析任务逐块处理而非静默截断；项目归纳使用这些结果及原文关联证据。会议分析必须读取完整原始转写、人工校对文本、会议记录、关联项目背景、上一次总结和名称词表；不能只对旧纪要再次压缩。

会议先拆分带原文依据的议题，再根据项目目录名、背景名称与受控别名匹配。每个自动关联必须有该会议中的原文引用，且只可选本人项目。分别生成每个项目的本次进展，原文完整保留。缺乏依据时保留待归类，不能猜项目。人工修改会名/关联后保留人工选择，不被下一次自动任务覆盖。

原始资料、此前方案和本次决定分别标识。旧方案内的AI设想、设备数量、分期不能被误写成会议新决定；推荐明确为建议，无会议依据不拆一期二期。原文与背景冲突时标记待核对，不用模型自行决定。

## 数据与任务

新增会议所有者、多项目关联、分析状态/摘要、名称纠错表、项目目录绑定、文件源修改时间、文件分析结果、项目进展与持久任务。后台任务使用数据库唯一输入指纹、状态、占用令牌和到期时间；重复同步不重复调用模型或追加相同进展，失败有状态且可重试。任务执行不阻塞录音或HTTP主线程。

数据库保存进展与证据作为真值，各项目docs/项目进展.md以临时文件加原子替换生成可读副本，保留按时间排列的历史条目。该文件不反向导入，避免循环总结。写入失败不能伪报持久化成功，重试不会重复条目。多项目录音分别更新各项目，不能将其他项目的结论混入。

名称纠错维护人员、公司、项目、术语的标准名和别名，可按项目或个人全局作用；自动归纳使用词表，原始转写保持不变，可追溯识别前后的内容。别名冲突拒绝或明确作用域，不建立声纹身份推断。

## 模型、GPU与验收

密钥从用户指定文件读取，写入被忽略的本机.env，只在服务端使用。先测试供应商模型与JSON能力，再配置调用；错误信息与日志不含密钥。声学识别继续本地运行。GPU独立环境实测CUDA、显存与耗时；显式指定GPU失败应明确报错，不伪装GPU成功。

验收涵盖无表单开始录音、多项目原文证据、上下文连续、文件真实时间、改名保留、词表、幂等同步、任务失败恢复、目录越界、用户隔离、MD持久化及网页刷新。真实资料导入正常库，测试工装仅写隔离库。GPU和AI实际调用有运行证据后才记为通过。

## 实现选择

沿用当前FastAPI/SQLAlchemy任务和同步体系，增加持久分析队列，复用现有文件与权限模型。一次性整目录摘要会丢失长资料和版本来源；纯向量检索不足以保证会议全文覆盖，因此采用逐文件分块分析、会议全文议题提取与项目上下文归纳的组合。保留今后接入向量检索的边界，不在本轮引入额外编排平台。
