# 紧凑项目工作台

2026-10-15；替代旧版界面中独立的会议、节点分页和大卡片布局。业务资料与确认记录仍保留。

## 页面

首页直接开始录音，展示最近项目与会议。项目管理使用紧凑列表，项目名称旁提供修改和信息补充。项目详情保留概览、文件、问题；顶部为确认进度环、完整流程标记、一段当前摘要及可展开建议。摘要可点击展开。

概览采用纵向时间轴，先显示发生日期，再显示一句摘要，详情及原件折叠。流程节点使用短行和明确的确认按钮，确认、修改、撤回均保留依据、实际发生时间和操作记录，并触发项目 Agent 重新分析。编辑项目只包含项目名称和客户名称。

文件按 Word、Excel、PDF、录音等显示图标；客户、我方、来源待确认使用低饱和色标。只从“客户提供、甲方提供、我方提供”等明确标记识别提供方，不从“客户确认流程”等文件主题推断。可在预览中修改提供方，修改后进入项目分析上下文。Markdown 预览支持标题、强调、列表、表格；不执行文档内 HTML，不自动请求外部图片。

每页仅设置一个上级返回入口；四个全局导航入口保留。手机字号不低于14px，标题、资料名称及摘要在列表中省略，完整文字通过详情可达。产品卡片直接展示产品介绍及资料，工作台保留真实项目状态、风险和开发快照。

## 归组与日期

同一来源目录、同名、同版本的 Word/PDF 合并展示，转换跨日不拆组，排序使用该组最新资料时间。录音、转写、纪要按原始主题和来源范围合并，全部原件入口保留；不只凭同一天或同名跨目录归并。重复主题有多场会议时还需匹配日期，无法明确关联时分别展示。原件及原始记录不合并删除。

导入录音只从真正文件名提取明确年月日和时间，不使用上层归档目录日期。支持紧凑日期、年月日及常见分隔符；只有日期时不补造时刻。未知会议日期不当作文件修改日期展示。

数据库、架构、接口、UI、测试及部署等内部研发资料按日概括开发进度，时间轴不逐件列出；文件页仍可查看原件。AI使用完整原文分片、会议转写、既有背景、历史总结、人工确认及本次要求，原文证据和跨项目隔离保持原有约束。

## 开发快照

绑定目录每日首次扫描建立或更新代码快照；同日刷新读取当天记录，不宣称实时工程完成率。后台每小时检查是否缺少当天快照。首次建立基线，不将既有代码计为当天新增；后续统计距上次快照的新增、修改、删除。Git摘要覆盖上次快照到当前扫描时刻，最多40条并明确标记上限；无Git仍使用哈希差异。快照前不读取密钥配置、依赖、输出、docs及链接目录，不把代码正文发送给模型。项目Agent接收快照结果。首次快照之后的变化在下一日快照体现。

## 2026-10-15 晚间调整

- 录音：首页底部固定“开始录音记录”，开始后不跳页；录音状态条在所有页面常驻，可随时停止。停止即保存并结束会议，交给 AI 命名与归类。隐藏页签时不判定输入中断，系统挂起先尝试恢复，麦克风短暂静音给 3 秒宽限；录音期间申请屏幕常亮。
- 导航：一级页面（首页、项目管理、产品库、工作台）顶栏显示品牌与页名，不显示返回；二级及以上页面只显示返回。
- 工作台不再列项目跟进，只放跨项目信号：节点/风险/开发/AI 整理统计、各项目整理队列、开发日报、风险跟进、文档进度。
- 概览：同目录同一天的多份资料合并为一条；旧版“此前……未见决定”类摘要不再展示。项目分析完成后追加一次时间轴整理（`timeline_digest`），结合项目总结为每条生成一句标题和 2–3 句说明，按条目文件集合哈希缓存；失败时保留确定性文字，不阻塞项目总结。项目总结扩为 100–180 字连贯段落。
- 未确认节点收为顶部“下一个节点”条和“确认已完成”按钮；已确认节点进入时间轴。
- 分析队列默认 3 个并行 worker（`ANALYSIS_WORKERS`，1–6），SQLite 等锁 30 秒；项目文件整理完后其项目总结优先执行。`/api/projects/{id}/workflow` 的 `analysis.queue` 返回待整理、进行中、失败、完成数。

## 2026-10-15 夜间：Agent 参谋与进度百分比

### Agent 链路（每个项目）
1. **逐份阅读**：file_chunk / meeting_chunk → 每份资料一句摘要（按指纹缓存，不重复读）。
2. **项目推理 project_review**（结构化 CoT，先推理后结论）：
   `thinking{facts, changes(对比上次判断), stage_reasoning, gaps}` → `stage + stage_progress` → `nodes[8]` → `summary/next` → `actions[2-4]` → `questions` → `risk_ids`。
   缺少 thinking 时追加一次纠正调用。
3. **确定性护栏 checked_insight**：人工确认节点必为 done、stage 不早于确认节点、done 必须有依据、已采纳/忽略过的建议不再出现。
4. **自检 project_reflect**：审稿人对照资料摘要与事实检查判断；只能把判断改得更保守（done→doing、stage 最多移动一个节点、删除空泛建议），问题写入 `thinking.review`。
5. **时间轴说明 timeline_digest**：结合项目总结写每条历程的标题与说明（缓存复用）。

### 记忆与学习（"训练" CoT 的方式：上下文学习，而非微调）
- `previous_insight`：上次的阶段、进度、建议，用于输出"变化"。
- `manager_feedback`：本项目对建议的采纳/忽略（含理由），采纳自动生成任务。
- `manager_preferences`：其他项目的采纳/忽略倾向，调整建议风格。
- `manager_questions`：经理问过的问题，下次推理会回应。

### 触发
资料新增/变化、会议结束、节点确认、采纳/忽略建议、提问、手动"重新思考"、每天首次（指纹包含日期，每 30 分钟检查）。

### 进度百分比
节点完成时的累计权重：洽谈 5、需求 15、方案 28、合同 38、开发 70、交付 85、验收 95、维护 100。
整体进度 = 上一节点权重 + (本节点权重 − 上一节点权重) × AI 阶段内完成度；人工确认的节点为下限（环形图深色部分为已确认，浅色为 AI 评估）。

### 其他
- 时间轴时间：文件名/上级目录名中的日期优先（`business_time`），其次文件修改时间。
- 删除录音：`DELETE /api/meetings/{id}`，同时删除分片、转写、纪要、生成文档、分析记录；目录导入的原始录音保留在磁盘但脱离项目；录音中不可删除。
- 问 AI：`POST /api/projects/{id}/ask`，返回推理步骤、回答、依据、追问建议，问答进入项目记忆。
