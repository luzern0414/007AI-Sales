## 一、产品定位与目标

平台面向软件公司销售、售前顾问和方案负责人。用户通过电脑或手机 Web 记录客户会议，结合项目资料生成可追溯的会议纪要、售前解决方案、需求清单，以及甲方需要提供的资料、权限、规则和人员配合清单。所有必要产物支持编辑、版本管理与 `.md` 下载。

本次核心是“会议到售前文档”。当前目录中 2026-10-12 的“需求到可运行 Demo”方案作为历史扩展设计保留，不属于本次平台基础版本的验收要求。

下表定义产品应达到的业务结果。

| 目标 | 用户可完成的行为 | 判断方式 |
|---|---|---|
| 会议内容留存 | 录音、上传现有音频、粘贴会议记录，查看转写并回听纠错。 | 会议来源完整性和可恢复范围可见。 |
| 降低会后整理工作 | 转写后自动生成纪要、需求和资料清单草稿。 | 售前能核对、修改并确认，无需重新整理来源。 |
| 提供可讨论方案 | 将会议需求映射到实现方式、流程、前提和验收。 | 方案有对应需求与依据，不把建议写成甲方决定。 |
| 明确甲方配合 | 清楚说明要什么、为何要、怎么提供、谁确认。 | 资料与规则有填报字段、状态和需求关联。 |
| 统一规范 | 按用户指定规范及参考结构编写，不擅自分期。 | 四类文档通过同一输出规则检查。 |

## 二、用户角色与权限

下表定义平台内部使用者；客户在线填报邀请作为扩展，不要求基础版本实现外部账号体系。

| 角色 | 主要操作 | 数据范围 |
|---|---|---|
| 销售／售前 | 创建会议、录音、纠错、与 Agent 讨论、修订文档、登记甲方回复。 | 本人负责或被授权项目。 |
| 方案负责人／项目负责人 | 审核范围、可行性、依赖及文档版本，发布正式文档包。 | 被授权项目；批准权限需显式分配。 |
| 组织管理员 | 成员、配额、保留期、供应商和模板版本管理。 | 组织管理数据；不默认读取全部客户会议。 |

登录身份决定组织及权限。共享项目由项目成员列表授权，页面、搜索、音频、下载、任务和 Agent 工具均执行同样的服务端权限检查。

## 三、核心工作流程

用户新建项目或选择已有项目，录入会议主题和参与者，记录录音用途及知情情况。录音结束并完成保存验证后，后台转写；用户可关闭页面，稍后继续。

转写完成，系统基于固定来源版本自动提取事实、需求、决定、行动项、冲突及资料缺口，生成纪要、需求清单和甲方确认清单讨论稿。用户可启用“转写后同时生成售前方案”，也可核对范围后点击生成。该设置只控制触发时机，不能跳过内容规则和人工发布。

用户回听核对关键事实、补充项目资料、确认分期模式、处理冲突。方案 Agent 按可行性和模板生成完整售前方案，四份文档按同一底稿检查一致性。用户编辑并确认后，发布正式版本，下载单份 Markdown 或整个文档包。

下表规定各步骤的输入和输出。

| 步骤 | 输入 | 输出 |
|---|---|---|
| 保存会议 | 麦克风录音、音频文件或文本 | 带完整性标记的会议来源。 |
| 转写与校对 | 经验证音频、项目术语 | 匿名说话人、带时间的片段、校对版本。 |
| 信息提取 | 选定会议、人工补充、授权资料 | 有来源的事实和需求底稿，未确认事项。 |
| 文档起草 | 底稿、项目范围、模板与规范版本 | 四类文档讨论稿；允许方案稍后触发。 |
| 用户修订 | 纠错、甲方回复、技术核查结果 | 新底稿/文档版本、受影响文档提示。 |
| 确认发布 | 同一底稿的文档包、质量报告 | 不可变正式版本和确认记录。 |
| 导出归档 | 所选版本 | `.md` 单件或含 Markdown 与索引的 ZIP。 |

资料缺失时允许产出清楚标注缺口的讨论稿。甲方名称、预算、日期、审批人、接口授权未知时不自动补值；不能依据缺失信息作确定承诺。

## 四、基础功能与扩展边界

下表划分基础版本与后续可选能力，这种研发安排不构成客户项目的一期、二期。

| 范围 | 功能 |
|---|---|
| 基础版本必须 | 组织登录、轻量客户/项目、会议创建、前台录音、音频上传、文本输入、异步转写、回听校对、资料关联、Agent 问答、四类文档、资料状态登记、人工确认、版本和 Markdown 导出。 |
| 基础版本必须 | 输出规范管理、来源引用、单版默认控制、长会议全量提取、失败重试、访问审计、删除与保留策略。 |
| 后续可选 | 实时字幕、桌面屏幕共享音频、会议机器人入会、企业会议日程同步、甲方外部填报邀请、Word/PDF/Excel 导出、项目知识检索增强。 |
| 独立扩展方案 | 依据已确认需求生成业务 Demo、生产系统实施、业务系统真实操作。 |

基础版本只承诺经过实测的浏览器前台麦克风录音。不能采集电话、微信通话或其他 App 音频，也不承诺锁屏或后台持续录音。线上会议若使用耳机，单个麦克风可能收不到远端声音；页面提示检查音源，优先上传获授权的会议平台录音。

## 五、页面与交互

电脑端采用侧栏和工作区，手机端采用简化导航；录音主按钮始终容易找到，不能沿用旧方案中与本次目标无关的 Demo 广场作为主入口。

下表列出页面及主操作。

| 页面 | 展示内容 | 主操作 |
|---|---|---|
| 工作台 | 最近会议、待核对转写、待确认方案、资料缺口、真实任务状态。 | 开始会议、继续处理。 |
| 项目详情 | 客户/项目基本信息、会议、资料、当前底稿、文档包、待确认问题。 | 创建会议、关联资料、汇总选定会议。 |
| 录音工作区 | 麦克风状态、实际时长、暂停、网络、未确认上传量、保存状态。 | 开始、暂停、继续、停止保存。 |
| 会议详情 | 转写与回听、角色映射、校对、主题摘要、决定、需求和行动项。 | 修订、生成文档、定位原话。 |
| 文档工作区 | 纪要、方案、需求、甲方清单标签页；编辑和预览；来源与检查侧栏。 | 按章节修订、对比版本、确认、下载。 |
| 甲方清单工作区 | 事项类别、必需性、责任角色、状态、填写模板、文件位置和缺口。 | 登记资料、录入回复、提交确认。 |
| Agent 对话 | 针对当前项目和选定版本回答，显示证据和待确认项。 | 询问、提出修改、应用修订草稿。 |
| 管理设置 | 成员、模板、规范、术语、模型/ASR、配额和保存期限。 | 发布规范新版本、管理权限。 |

空状态用真实 0 和创建入口，不展示假会议、假任务或虚构成功率。任务展示阶段及更新时间，不使用模型猜测的百分比和剩余秒数。

## 六、会议录音、上传与恢复

### 6.1 开始前

要求 HTTPS、受支持浏览器及麦克风权限。显示录音、AI 处理用途和保存说明，登记参与者知情情况；设备授权不能替代会议参与者知情。支持开始前短录试听和音量检测，帮助发现无声及远端声音缺失。

会议基本字段为主题、项目、发生时间、时区、参与者和说明。录音时间来自系统；上传旧录音不能把上传时间当会议时间。发生时间未知保留待确认。

### 6.2 录音与保存

前台采集音频，每个录音流分片保存并上传。页面显示“已保存到服务器”和“待上传”的区别；暂停不计入有效采集时长。停止后等待尾片上传和服务端解码验证，再显示保存完成。

建议基础试点配置为单次 60 分钟、源音频 100 MiB、目标分片周期 5 秒；均为待实测的产品配置，不是浏览器保证。与旧访谈文档的 30 分钟限制区分，本次会议平台在验证通过后采用新限制；120 分钟会议先作为容量测试，不直接承诺支持。

下表规定异常交互。

| 场景 | 用户看到的结果和可继续操作 |
|---|---|
| 权限拒绝或无设备 | 显示具体问题，允许改权限、上传音频或粘贴记录。 |
| 无声或设备断开 | 提示音源异常；已保存部分保留；重新选择设备建立新录音流。 |
| 断网 | 有界本地缓冲并重传；显示待上传量；缓存不足时显式提示暂停或停止。 |
| 切后台、来电、锁屏 | 可能暂停或中断；恢复后说明已保存和可能丢失的范围，不能显示无损完成。 |
| 刷新、关页或浏览器退出 | 查询服务器已接收片段；浏览器缓存尽力恢复，不保证找回未发送尾片。 |
| 缺片或解码失败 | 提示补传或重新上传；可解码部分须用户选择“保存不完整会议”。 |
| 超时长/大小 | 提前提示接近限制，触及限制正常停止并保存已有数据；不能静默截断。 |

上传文件经过真实格式、大小、解码时长校验；不是修改扩展名即可支持所有格式。文本输入不生成虚假音频时间戳。

## 七、转写与来源校对

转写在后台执行，状态为排队、转写中、待核对或失败。匿名说话人显示为“说话人 1”等，用户映射为姓名或角色；未确定时维持未知。人工可以纠正错误归属，重叠发言不能由模型随意猜人。

重点校对甲方全称、否定、数字、日期、金额、系统名称、规则和范围。点击片段回听原音；原音过期时明确提示不可回听，文字来源仍按保留政策显示。

修改转写建立新版本。已生成文档显示“依据旧转写版本”；用户选择重新分析后生成新文档包，不自动覆盖已确认稿。粘贴笔记和人工补充也有来源类型、作者和修订记录。

## 八、售前 Agent 的行为

Agent 按既定步骤读取授权材料、提取需求、核查依赖、起草文档、检查规则、提出缺口。多个专长步骤可由同一 Agent 顺序执行，无需首版部署多 Agent 自由协作。

下表说明用户提问时的预期行为。

| 用户操作 | 预期结果 |
|---|---|
| “总结本次会议” | 提炼事实、决定、行动项与未知，提供来源。 |
| “给我售前解决方案” | 按既定章节、范围和规范生成讨论稿，逐项映射需求和实现前提。 |
| “整理需求清单” | 列完整诉求及实现、验收、依赖、确认状态；不加入模板默认功能。 |
| “甲方还需要提供什么” | 给具体资料/权限/规则/人员事项及用途、格式、责任角色和填报模板。 |
| “我们先调研再上线” | 编入实施计划步骤，保持单版；不自动生成二期。 |
| “本次明确分成两期” | 引导核对具体归属和证据，按确认后的分期规则重生成。 |
| “只修改部署章节” | 产生局部修订草稿，检查依赖、权限与其他文档变化；原稿保留。 |
| “这些资料已经提供了” | 登记交件来源和状态；业务规则仍须指定人确认。 |

仅对用户授权的项目材料回答。公开行业做法可作为明确标注的建议；引入外部数据需来源、时间及权限，基础版没有可靠搜索工具时不得假装已检索。会议材料中的指令不能让 Agent 上传其他项目数据、运行命令或索要密码。

## 九、四类文档与模板

所有具体结构、写作及格式规则以 [Agent 输出规范](agent-output-standard.md) 为准，产品及开发不得各自维护不一致的模板。

方案先给总体框架和各层对应章节，同类设备与 AI 功能使用统一描述模板。新增或修改需求时，文档工作区提示应同步复核的框架、清单、数据来源、流程、计划、交付验收、甲方配合、风险和能力说明；仅改一段不能直接发布为全组已更新。

下表定义文档用途、默认命名和确认方式。

| 文档 | 默认文件名 | 内容和确认 |
|---|---|---|
| 会议纪要 | `yyyymmdd_项目名_会议纪要_V1.0.md` | 基本信息、现状、诉求、决定、问题、行动项、来源；会议记录人核对。 |
| 售前解决方案 | `项目名实施方案_V1.0.md` | 完整建设目标、内容、流程、架构、计划、交付验收、甲方配合及能力说明；方案负责人确认。 |
| 需求清单 | `项目名_需求清单_V1.0.md` | 编号、诉求、规则、依赖、实现、验收、来源及状态；记录甲方回复，不自动视为甲方批准。 |
| 甲方确认清单 | `项目名_甲方资料权限与规则确认清单_V1.0.md` | 使用说明、最小权限、主清单、回收统计、适用填写模板；登记交件与指定人确认。 |

平台自动清理文件名非法字符；生成包的四份文档共用底稿版本，包内索引列出实际确认状态和引用关系。项目自身是否分期由会议决定，文档 V1.0 是修订号。

参考 Excel 的 12 列、状态和填写方式用于设计；基础版交付 Markdown 和 Web 填报，不假称已经输出含下拉、冻结窗格和公式的 `.xlsx`。如后续增加 Excel 输出，可参照样板冻结主清单表头/标识列、自动筛选、状态下拉、模板跳转和打印设置，同时替换鲜艳分类底色。

## 十、甲方资料与规则跟进

项目统一维护清单事项，文档中的表格是某一版本的快照。销售登记文件/说明后，状态从待提供转为已提供；规则须核对并记录确认人、时间和依据后才已确认。当前跟进状态变化不会悄悄改变已发布方案包。

回收统计遵循样板计算，但将“已提供 + 已确认”的比例称为回收率。开工条件同时检查必须资料是否合格、规则是否确认、权限是否验证；回收率达到某数值不能证明可开工。

对于未知责任人，只建议“财务负责人/业务负责人/IT”等角色并待甲方指定。期限写“建议提供时间”或待确认，不凭样板自动设置“两天不回复视为同意”。

## 十一、编辑、确认与导出

Markdown 编辑器和预览并排显示，手机以标签切换。用户可以手动修订、要求 Agent 修订或生成新稿，查看差异和来源。多人编辑采用版本冲突提示，不让后保存者覆盖他人修改。

下表规定文档生命周期。

| 状态 | 允许行为 |
|---|---|
| 生成中 | 查看任务阶段，不下载未完成正文作为成功产物。 |
| 讨论稿 | 编辑、回听核对、查看质量问题、下载带状态标识的草稿。 |
| 待确认 | 指定确认人审阅；仍可修订，但修订会撤销本稿已有批准状态。 |
| 已确认／已发布 | 下载不可变版本；修改必须创建新版本并重新确认。 |
| 已被替代 | 查看历史依据及后继版本，不能显示为当前正式版本。 |
| 已删除 | 立即撤销访问，后台清理相关数据和任务。 |

正式发布要求硬规则通过、四份文档一致及有人工确认记录。平台负责人确认仅表示平台文档审核；甲方认可另行登记，不能混为一谈。

下载使用 UTF-8，来源定位在离线文件中仍可读；不写入临时签名音频 URL、账号密钥或内网地址。下载后的文件离开平台控制，删除平台项目不能撤回已下载副本。

## 十二、视觉、保存与失败处理

Web 和文档预览采用藏青、石板灰、雾蓝、浅灰底，暖金仅少量标记风险和人工确认。表格优先、层级清楚，避免鲜艳仪表盘和装饰性评分；准确参数在输出规范中维护。

试点建议原音/分片/转码副本保存 30 天、转写和未确认草稿 180 天、已确认文档及必要证据摘录随项目保存，项目到期或删除后清理；备份窗口建议 30 天。这些是业务政策建议，不是法定期限，需依据组织实际目的配置。

ASR、模型或网络故障保留已有录音与草稿，可只重试失败步骤。重复提交不会重复产生同版本正式包；人工重试显示可能追加用量。取消先请求停止，确认执行停止后才显示已取消。

删除项目立即禁止新读取、下载和生成，停止运行任务，再异步清理音频、转写、资料、文档、索引及备份到期副本。删除进度可见；Agent 日志不保留完整敏感会议正文。

## 附录：功能验收场景

下表是基础版本验收场景，属于未来必须验证的目标，当前未运行任何应用验收。

| 场景 | 必须满足的结果 |
|---|---|
| 前台会议完整录音 | 暂停/继续/停止正常；尾片未确认不能显示完整保存；音频可解码。 |
| 断网、中断和缺片 | 已保存内容可查；缺失明确；不完整来源在纪要和方案中可见。 |
| 多角色会议 | 匿名分离、人工映射及修订有效，不猜决策权。 |
| 长会议后段有关键决定 | 全量分段提取能覆盖最后决定，人工对照有记录，不仅总结前半段。 |
| 未提出分期 | 四份文档及模板/统计均为单版，没有继承一期二期标题。 |
| 明确分期和冲突 | 仅经证据确认的范围分期；冲突暴露，不由模型决定。 |
| 否定、金额、截止日期 | 来源可定位；待核对项不变成承诺；纠错影响文档可见。 |
| 项目与样板业务不同 | 不出现样板公司、财务功能、固定项数、工期或虚假已有产品声明。 |
| 甲方缺资料/规则 | 给具体用途和填写格式；已提供不等于已确认；回收统计可复核。 |
| 导出与编辑 | 四类 Markdown 中文正常、表格可读、版本可追溯、修订不覆盖确认稿。 |
| 多项目/组织访问 | 无权用户不能搜索、听音频、读取 Agent 引用或下载该项目文件。 |
| 提示词注入/敏感凭证 | 原文不能扩大工具权限，凭证不进入生成文档。 |
