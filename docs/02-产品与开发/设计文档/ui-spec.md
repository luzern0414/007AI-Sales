# Web AI 销售助手四页 UI 与交互规范

版本：V2.0 设计稿；日期：2026-10-15，Asia/Shanghai。本文件交付文字线框与视觉/交互规范，没有应用页面、截图或可执行原型。手机优先与页面职责以[项目交付设计 V3](project-delivery-design.md)为准；以下保留 V2 线框供复用，不作为当前项目管理、面客产品库和工作台的最终页面。当前导航固定为 **首页、项目管理、产品库、工作台**。业务、保存协议与导出详见[实时平台设计](realtime-platform-design.md)，产物内容遵循[输出规范](agent-output-standard.md)。

首页是客户现场会议工作区，主要面积给实时文字和真实保存状态。历史用于找会议与下载，产品库用于核实推荐依据，工作台用于形成方案和清单。采用藏青、石板灰、雾蓝和浅灰，保留留白、清楚层次与少量暖金提示，避免鲜艳多色背景、机器人装饰和无意义统计卡片。

## 一、统一布局与视觉

| 项目 | 设计值初稿 | 使用约束 |
|---|---|---|
| 主色 | `#1F3A5F` | 主按钮、选中导航、重要标题 |
| 次色 | `#3E5C76` | 层级标签、图表骨架 |
| 辅助雾蓝 | `#7489A3` | 箭头、非文字辅助，不默认用作低对比正文 |
| 页面/卡片 | `#F5F7FA` / `#FFFFFF` | 大面积低饱和底色 |
| 边线 | `#D5DDE6` | 卡片分隔；交互控件边界另验对比 |
| 正文/次字 | `#1F2933` / `#66727F` | 正文和辅助说明，逐实际底色验证 |
| 确认/风险 | `#A8875A` + `#F7F2EA` | 暖金少量强调；配图标与文字，不只靠颜色 |
| 严重异常 | 低饱和深红文字/边框 | 仅阻断故障或危险操作，不当品牌主色 |
| Web 字体 | Microsoft YaHei、PingFang SC、Noto Sans CJK SC、system-ui、sans-serif | 实际系统可用字体；不强制下载商业字体 |
| 正文/行距 | 14–16px，1.6 | 转写正文 16px，长文本优先可读 |
| 标题 | 页面 24–28px；区域 18px；子标题16px | 简单一致，避免满页大标题 |
| 数字/时间 | tabular-nums，必要时等宽字体 | 对齐计时、水位、金额与表格 |
| 布局 | 桌面侧栏220px，顶部64px，外边距24px，间隔16/24px | 1280px以下右栏可折叠；以内容验证 |
| 卡片/控件 | 卡片圆角10px，细边线/轻阴影，控件约40px高 | 主行动有明确焦点，移动触控区至少约44px |
| 图标/动效 | 同套线性图标；150–200ms轻量反馈 | 本地资产/许可登记，支持 reduced motion |

Web 阅读字体与 Word/PDF 格式独立。正式文档仍按黑体、宋体、Times New Roman及指定字号；Web系统字体好看不代表 PDF 符合规范。暖金/雾蓝和状态文字都必须按最终背景测对比，不能因为色板固定就宣布可访问性达标。

桌面采用统一侧栏及顶部项目/账户栏；宽屏内容最大合理阅读宽度约1440–1600px，表格可占满宽度。手机采用四项底部导航，正在录音时在导航上方固定简化录音条；所有页面都有当前位置与当前项目。管理和账户菜单不加入第五个底部入口。

## 二、首页：会议记录和保存始终可见

首次进入显示“开始客户会议”和恢复草稿（若存在），选择客户/项目、主题、参会者、麦克风。麦克风预检显示输入电平、设备名、权限和本机空间状态；“电平有变化”不能写成“所有参会者均已录到”。开始录音前用简短信息说明录音/转写目的和前台限制，设备授权失败给具体恢复步骤。

下图时间仅为示意，不是性能或恢复承诺。

```text
┌────────────┬───────────────────────────────────────────────────┐
│ 销售助手   │ 客户 / 项目 > 当前会议                 项目 / 账户 │
│ 首页 ●     ├───────────────────────────────────────────────────┤
│ 项目管理   │ 客户需求沟通会                    录音中 00:24:18 │
│ 产品库     │ [会议室麦克风⌄] 电平 ▂▅▃  [暂停] [结束] [重点]   │
│ 工作台     ├───────────────────────────────┬───────────────────┤
│            │ 实时文字             [搜索]   │ 会议要点          │
│ 最近项目   │ 00:22:05 发言人 A · 该句稳定   │ [速记][决定][问题]│
│ 客户 A     │ 当前发言原文…… [标记重点]     │ 人工速记……        │
│ 客户 B     │ 00:24:16 发言人 B · 识别中     │ 待确认问题……      │
│            │ 当前正在变化的文字……          │ 追问建议（可关闭）│
│            │ [跟随最新：开]                │ [添加速记]        │
│            ├───────────────────────────────┴───────────────────┤
│            │ 音频时间轴 ──重点──暂停──缺口──                   │
│            │ 本机已保存 00:24:16 · 服务端已保存 00:24:12       │
│            │ 待补传 4 秒 · 文字稳定至 00:24:09 · 网络正常      │
└────────────┴───────────────────────────────────────────────────┘
```

录音计时、实际录到音频、文字识别、本机保存、服务端保存和待补传分开显示。主条写用户能理解的“本机已保存至/服务端已保存至”，实现中的seq、OPFS、PCM不出现在正常流程。采样心跳还须独立监控：超时显示“未检测到新的录音输入”，不能仅因本机/服务端两个冻结位置一致就写保存完整。技术诊断可在展开详情中提供。连续水位未追平时不写“全部安全保存”；有中断显示“存在未记录区间”并可定位。

| 操作 | 交互规范 |
|---|---|
| 开始 | 确认设备和麦克风授权，建立会议；按钮立即给操作反馈，实际采样开始后才“录音中” |
| 暂停/继续 | 状态变更在固定位置，时间轴标计划暂停；继续可创建新采集段，不伪装无缝音频 |
| 标记重点 | 当前时间点快捷标记，支持选文字标记；用户可改标签，不自动改变事实确认 |
| 实时文字 | partial 同片段替换，“识别中”与“该句稳定”区分；流式稳定不等于会后核实 |
| 阅读历史 | 手动上滚关闭跟随，显示“有新内容”；不抢光标，不因更新重排已读位置 |
| 手工速记 | 异步自动保存、显示成功/失败；发言原文和速记来源区分，不能混作甲方原话 |
| 回放 | 稳定片段点时间跳转；未归档范围提示尚不可回放，不伪造播放器可用性 |
| 结束 | 停采集、保存尾部、补传和完整性检查；待补传时可保留本机草稿，明确恢复入口 |
| 结束后 | 显示回放/校对、生成纪要、进入工作台；不只弹一次消失的完成提示 |
| 跨页 | 录音运行时保持，全局状态条可回首页；并发录音由唯一所有者控制 |

首页恢复卡显示会议名、最后本机与服务端位置、待补传量、“恢复已保存内容/继续录音”两个动作；继续录音需要重新授权并新段，恢复数据不代表补录中断期间声音。

## 三、项目管理：记录完整性和版本一起可查

默认最近会议列表，可按客户、项目、日期、待校对/待确认/已确认、存在缺口筛选。搜索范围是本人有权会议；列表不泄露无权客户名或命中片段。空白页引导“开始会议”，无结果页保留当前筛选并提供清除。

```text
┌────────────┬───────────────────────────────────────────────────┐
│ 首页       │ 项目管理                     [搜索会议/客户/内容] │
│ 项目管理 ● │ [客户⌄][项目⌄][日期⌄][状态⌄]     [开始会议]      │
│ 产品库     ├───────────────────────────────────────────────────┤
│ 工作台     │ 会议主题      客户   日期  时长  完整性  纪要状态 │
│            │ 需求沟通会    客户A  10/15 58分 完整    待确认   │
│            │ 接口沟通会    客户B  10/14 36分 有缺口  待校对   │
│            │                                     [PDF][MD]    │
│            ├───────────────────────────────────────────────────┤
│            │ 选中会议详情                                    │
│            │ [纪要][逐字稿][录音][版本与关联方案]              │
│            │ 纪要 V1.1 · 待确认 · 来源文字 V3                 │
│            │ [编辑校对] [进入工作台] [下载当前版本 PDF]        │
└────────────┴───────────────────────────────────────────────────┘
```

会议详情保留音频时间轴、说话人映射、缺口、文字版本、四类关联文档和确认记录。版本切换明确当前/旧版；源稿修改导致旧 PDF 显示“来源已更新，建议重新生成”。下载按钮分别叫“纪要 PDF”“纪要 MD”“录音”，不以一个“下载”混淆附件。

PDF未生成时显示“生成 PDF”，生成中显示后台任务并允许离开，失败保留 MD 下载和重试。就绪才“下载 PDF”；用户再次进入可恢复任务状态，不能要求重做录音或再调用整个Agent。讨论稿 PDF 使用明显状态和未确认字段，按钮不暗示甲方已批准。

## 四、产品库：已核实能力、限制和来源同屏

产品库面向企业自有产品资料，不是互联网插件市场。产品卡呈名称、类别、当前有效版本和审核状态；表格模式便于批量管理，采用同一视觉系统。

```text
┌────────────┬───────────────────────────────────────────────────┐
│ 首页       │ 产品库                      [搜索产品/功能/型号] │
│ 项目管理   │ [分类⌄][状态⌄][版本⌄]         [新建产品][上传资料]│
│ 产品库 ●   ├────────────────────┬──────────────────────────────┤
│ 工作台     │ 产品卡/列表        │ 产品详情：产品 X / 版本 3.2  │
│            │ 产品 X · 已核实    │ [概况][能力][资料][商业信息] │
│            │ 产品 Y · 待补资料  │ 能力     核实  条件/限制 来源│
│            │ 产品 Z · 已停用    │ 功能 A   已核实 需接口   p12 │
│            │                    │ 功能 B   规划中 不可承诺 p18 │
│            │                    │ 原件/版本/核实人/有效时间    │
└────────────┴────────────────────┴──────────────────────────────┘
```

能力行给“已核实/待核实/规划中/不可承诺”文字，点击证据定位原 PDF 页码、文档段落或工作表单元格。限制不能隐藏在折叠免责声明中，应紧挨能力。资料解析 queued/处理中/待审核/失败/可用分别显示，上传成功不等于知识核实成功。新版本不覆盖旧版，历史方案展示当时产品快照。

报价/成本字段按权限显示；无权限不渲染真实值到隐藏DOM。普通销售看到面客批准报价，供应商成本单独权限控制。删除/停用资料前提示影响的索引与当前新生成，历史证据按保留策略可追溯。产品资料不足时给“补充能力证明/接口说明”等可执行动作，不自动填成“已支持”。

## 五、工作台：用同一底稿编辑四类产物

桌面三栏：左输入与产物树，中间编辑/预览，右证据与待确认。源事实修改与自由文本编辑区分；改内容后显示受影响章节，不立即静默覆盖人工改稿。

```text
┌────────────┬───────────────────────────────────────────────────┐
│ 首页       │ 工作台 / 客户A / 需求沟通会        V1.1 · 讨论稿 │
│ 项目管理   │ [生成/更新] [检查] [提交确认] [导出⌄]            │
│ 产品库     ├──────────────┬─────────────────────┬──────────────┤
│ 工作台 ●   │ 输入         │ [编辑][预览][差异]  │ [来源][问题] │
│            │ 会议文字 V3  │ 二、建设内容        │ REQ-003      │
│            │ 产品 X 3.2   │ 总体框架与各层说明… │ 甲方诉求…    │
│            │ 输出规范V1.1 │ 需求对应章节…       │ 会议00:12:34 │
│            │              │                     │ 产品手册p12  │
│            │ 产物         │ 待确认字段有定位标签│ 有前提：接口 │
│            │ ▸会议纪要    │ [重生本节]          │ [打开来源]   │
│            │ ▸售前方案    │                     │ 待确认5项    │
│            │ ▸需求清单    │                     │ [定位问题]   │
│            │ ▸甲方确认单  │                     │              │
│            ├──────────────┴─────────────────────┴──────────────┤
│            │ 已自动保存 · 需求有去向 18/20 · 2项需技术核查     │
└────────────┴───────────────────────────────────────────────────┘
```

图中数量仅为示意。显示真实计算的覆盖分子/分母和未覆盖原因，不用虚构百分比营造成效。四份文档共用REQ、范围和产品版本；新增需求触发框架、清单、业务流程、实施/交付/验收和甲方配合的影响检查。删除产品建议不能删除甲方原需求。

| 编辑/生成动作 | 行为 |
|---|---|
| 选择输入 | 明确当前会议转写、手工补充、产品有效版本，保存快照 |
| 生成方案 | 显示会议事实/产品事实/乙方建议来源区分，未确认工期和报价不填确定值 |
| 需求清单 | 横向滚动表格；移动端按REQ卡片读，字段可展开，状态保留 |
| 甲方确认单 | 使用说明、主清单、回收统计、专项表关联；已提供与已确认区分 |
| 自动保存 | debounce编辑保存和服务器版本冲突提示；保存失败有“重试/保留本机副本” |
| 重生选定节 | 比较旧/新内容，人工选择采用；受影响的关联章节待检查 |
| 规则检查 | 错误可点击定位；待确认非伪错误；关键无来源承诺阻止正式发布 |
| 人工确认 | 明示确认主体与修订范围，销售审核不命名“甲方已确认” |
| 导出 | 显示文件类型和当前版本；纪要 PDF可导出讨论稿；正式方案 PDF遵循已审Word路径 |

## 六、生命周期、空白与异常状态

录音/保存/识别各自呈现，用户可以辨认文字没有更新但音频仍保存的情形。正常页面不堆积工程告警，阻断风险才用可见横幅，附具体动作。

| 状态/事件 | 用户看到的文字初稿 | 可操作动作 |
|---|---|---|
| 未开始 | “准备记录客户会议” | 选设备、测试、开始 |
| 正常录制 | “录音中；本机已保存至…；服务端已保存至…” | 暂停、重点、结束 |
| 断网 | “离线录音，正在本机保存；待补传…秒” | 保持前台，查看空间，恢复后自动补传 |
| ASR不可用 | “录音继续，实时文字暂时不可用” | 继续会议，稍后补识别 |
| 手机离页/锁屏风险 | “请保持页面前台；系统可能中断麦克风” | 返回录音页，恢复后确认缺口 |
| 设备/权限丢失 | “录音已停止；最后保存至…，存在未记录区间” | 重选设备/授权，新段继续 |
| 本机空间不足 | “本机保存失败，请安全结束或处理空间” | 保存已有内容/查看服务端状态；不静默清待传块 |
| 再打开草稿 | “发现未结束会议；本机已存…；待补传…” | 恢复材料/重新授权继续 |
| 多页竞争 | “该会议正在另一页面录音” | 返回录音页面、仅查看 |
| 结束补传 | “录音已结束，正在补传…秒” | 保持页面或保留本机恢复，不能虚报完成 |
| PDF失败 | “PDF未生成：字体/排版/资源问题” | 下载MD、同版本重试 |
| 生成待确认 | “需要确认接口权限/产品能力后完善方案” | 定位具体问题，保留讨论稿 |
| 权限失效 | “当前无权查看此会议/资料” | 返回有权列表，不展示残留正文 |
| 输入版本冲突 | “内容已有新版本，请比较后保存” | 比较/另存草稿；不覆盖他人更新 |

空产品库指引上传并核实企业资料；无历史引导录制；工作台无输入引导选会议；无检索结果说明匹配依据不足并列待补信息，不推荐不存在的产品。任务超时/失败显示已保存产物和可重试步骤，刷新不丢历史状态。

## 七、响应式与可访问性验收

桌面≥1280px首页两栏/工作台三栏；768–1279px证据右栏折叠为抽屉；<768px实时文字占主要区域，要点/来源转标签页，四项底部导航常驻。移动录音条位于导航上方，避免覆盖正文末行和键盘操作；暂停/结束触控区稳定。表格横向滚动并保留编号，不能把字段全部挤成不可读小字。图表有文本等价摘要，会议长段不固定高度裁切。

实施时用真实中文长文、长名称、金额/日期、空白、异常和大清单检查排版。键盘可完成录音按钮、设备选择、列表筛选、来源跳转和编辑；焦点可见，弹窗焦点受控，关闭回原触发点。颜色之外有图标/文字状态，正文按 WCAG 对比要求验证；live region 只播关键状态，不每个转写字打断朗读。尊重 reduced motion，录音状态点可静态显示。触屏与键盘操作都不得依赖hover才发现。

验收需覆盖前台手机与桌面实机、缩放200%、键盘和屏幕阅读器、断网/ASR失败/强杀恢复/权限失效、旧PDF版本提醒、长表与长段。**本轮未执行这些页面验收**，视觉值为可实现初稿；后续真实页面必须保存截图与交互证据再宣称美化或可访问性完成。
