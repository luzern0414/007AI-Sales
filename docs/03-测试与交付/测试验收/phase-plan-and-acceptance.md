# 阶段路线与可审阅验收证据

状态：**方案草案，设计阶段路线**。日期：2026-10-12，Asia/Shanghai。
本文件定义阶段目标、依赖和证据，不是自动开始编码的命令，也没有任何阶段已通过的含义。

## 阶段安排原则

先把关键不确定性变成可测证据，再做业务闭环与模板生成，最后开放客户分享和多租户增强。
每阶段可独立展示产物；上阶段失败项必须解释处理，不以“模型生成了页面”跳过音频完整性、实际后端或隔离门槛。
计划以受控三模板为基线，生产交付、实时字幕、任意多 Agent 和真实第三方集成不列入首期承诺。

| 阶段 | 可独立交付结果 | 前置条件 | 时间假设 |
|---|---|---|---|
| P0 关键能力 PoC | 浏览器、ASR、provider、队列/沙箱及模板验证记录。 | 本方案评审、授权样本/企业测试账号、隔离环境。 | 1–2 周，假设小组与账号及时就绪；无工期保证。 |
| P1 会话到确认需求 | 手机采集/上传、转写校对、AI 聊天、需求草稿和冻结。 | P0 音频、ASR、模型/数据政策门槛。 | 2–3 周，取决于兼容/授权和语料。 |
| P2 三模板可运行 Demo | 真实前后端、任务与检查、内部独立预览及导出。 | P1 版本基线；P0 worker/队列/runtime 能力。 | 2–3 周，模板业务规则稳定为假设。 |
| P3 分享和组织硬化 | 私密客户分享、租户隔离、删除/保留及运营证据。 | P2 产物基线；强隔离和访问 gateway PoC 通过。 | 1–2 周，域名/网络/安全评估及时为假设。 |

估计适用于熟悉 React/Python、具备运维支持的小组，不能相加成为承诺上线日期。产品、研发与运维需按实际团队和实验结果重估。

## P0：先证明录音、模型和执行边界

### 浏览器与音频

设备矩阵至少包含 iPhone Safari、Android Chrome；微信内置浏览器单列候选，Wi-Fi 和 4G/5G 分开。
记录具体 OS/浏览器版本、实际 MIME/codec、分片大小和事件顺序。测试 5/30 分钟前台；60 分钟仅用于容量探索，不因此放宽默认 30 分钟政策。
覆盖权限拒绝/撤回、切后台/锁屏/来电、蓝牙路由、暂停恢复、断网、大 Blob、本地存储不足、刷新/关页/kill、多流和缺头/缺尾。
证据包括可解码源文件、最后事件/ACK 清单、缺失提示和服务器标准化结果；恢复不保证无损，必须列已恢复/丢失范围。
进入 P1 的条件是有明确经测试支持矩阵、finalize 不能跳过缺片/最终 ACK，以及失败时可操作降级；微信未过则只提示系统浏览器/上传。

### ASR 与需求模型

建议至少 20 段取得授权的脱敏访谈，包含行业术语、中英产品名、口音、噪声、远场、重叠、否定、金额和长停顿；样本量为设计建议。
同一标注语料比较阿里、腾讯、火山；自托管 FunASR/faster-whisper 作为成本/私有化候选时额外加入，不必须同时部署。
记录 CER、关键业务实体/否定/金额错误、DER、人工修订时间、P50/P95 完整处理时间、失败、账号计量及实际账单。报告样本边界，不填通用“99% 准确”。
需求输出由售前核对事实支持率、重要遗漏、冲突暴露、澄清问题价值和人工确认耗时；所选 Demo 的 critical ambiguity 必须可识别。
权重、SDK、模型与服务合同分别归档许可/地域/数据政策，供应商结果有效期不代替源音删除条款。

### provider 与 Agent 适配

具体型号/API/mode 验证普通 JSON、strict Schema 子集、function calling 参数/结果、多轮、流式、usage、拒绝、截断、empty content、限流、超时和取消。
首轮使用 Agents SDK 显式 Chat Completions adapter + 国内候选，证明默认 OpenAI tracing 没有外发；只允许受控 patch/read/list/fixed-check。
失败时以同模板、同预算比较 OpenHands SDK，不先并行维护多个引擎；raw chain-of-thought/敏感工具输出不进入页面。
证据需包含实际请求 metadata、能力矩阵、错误分类、全 retries 成本及脱敏安全摘要；没有真实账号则该门槛保留未通过。

### 模板、队列与沙箱

三模板先用固定栈、锁/hash、合成 seed 建立真实 CRUD 和重启/快照恢复检查基线。
验证指定 Celery/Valkey 版本的入队/ACK/visibility timeout、重复投递、worker lost、lease/fencing、旧 worker 回来、取消和 crash recovery。
隔离候选验证 Node/Python/SQLite/检查器兼容、CPU/内存/磁盘上限、出网规则、内网/metadata/DNS/IPv6、无 host/docker.sock、路径/符号链接和恶意依赖阻断。
外部分享前验证独立 runner + gVisor/微 VM/适当托管 sandbox；加固普通 Docker 内部结果不能直接作为外部分享批准。
托管候选额外测模型 API、控制 API、preview、依赖/镜像四链路的大陆网络及数据驻留/实际账单。

## P1：形成可确认且不丢来源的需求

可演示范围包括邀请账号、轻量客户/项目、前台录音/上传/文本、转写任务、角色人工映射、校对版本、销售与 AI 聊天、结构化需求及确认页。
首页只统计真实记录，0 状态明确；生成入口可显示未开放，不伪造 Demo 成功记录。

| 验收场景 | 必须提供的证据 |
|---|---|
| 重复上传及未确认最后片 | 同片 ACK 去重；finalize 不能提前成功。 |
| 录音中断 | 原件/可恢复部分、incomplete 标记和替代输入。 |
| 转写更正 | 原版保留，新 transcript_version，旧引用未静默改变。 |
| AI 推断/销售补充/客户原话 | source_kind、epistemic_status、confirmation 三维可见，引用真实。 |
| 关键歧义/外部接口未知 | 核心歧义阻塞该 Demo；未知外部接口明确 out_of_scope。 |
| 两设备确认旧稿 | 409 冲突，无旧版本覆盖新稿。 |
| 冻结后改聊天 | 新 draft，原 requirement hash 不变。 |
| 组织访问 | 跨租户接口/对象/下载不可见，server derives tenant。 |

P1 通过条件是售前代表完成端到端确认，且证据链和缺失提示正确；语义质量阈值由业务方基于 P0 基线确定并公开样本结果。

## P2：生成三个真实前后端模板

可独立内部展示 CRM-lite、工单、简单审批的 frozen spec → durable job → 限定 patch → 固定验证 → 独立预览/导出。
建议最多 3 主要实体、5 页面、1 主流程；超范围用明确缩减，不以模拟后端通过。
每用户/租户并发建议 1/2；每 attempt 从 lease acquisition 后的活动执行累计计时最多 15 分钟，排队不计入，恢复不能重置该 attempt 截止。人工 retry 新 attempt 仍受 job/租户总预算。
自动修复最多 2 轮；manual retry 独立 attempt，费用追加且保留历史。预算/时间上限到达必须停止。

| 验收场景 | 必须提供的证据 |
|---|---|
| 三模板业务流程 | list/create/get/update/delete、非法输入、主状态转换。 |
| 实际持久化 | 刷新、后端重启、SQLite 一致快照恢复、owner seed reset。 |
| 手机预览 | 小屏创建/编辑/详情操作及 console/network 摘要。 |
| 供应链边界 | 模板/镜像/锁/hash、允许 patch、禁改检查器/锁/策略有效。 |
| 故障/重投 | 同 job 无双份 published revision，fencing 旧 worker 无权发布。 |
| 取消/超时 | 真实进程/容器/凭证清理，不以 revoke 自报完成。 |
| 休眠/唤醒 | 保持合成数据、恢复 health，历史 succeeded 不改。 |
| 产物导出 | 源码/lock/seed/报告/许可齐全，无 key/原音/真实联系人。 |

统计首次检查通过、修复后通过、失败类别及全部成本，保留样本数。新需求版本标签及旧 Demo 依据必须可见。
P2 的内部演示成功不自动授权外部分享；缺少强隔离证据时 P3 分享保持关闭。

## P3：分享、租户、删除与运营

客户分享只到单 revision 业务端口，默认 7 天但有效期取政策与产物剩余寿命较小者，可立即撤销；不能发 sandbox admin/普通 wide preview token。
同 revision 多访客共享合成数据须告知，owner reset 提示丢弃；每客户数据副本不纳入本阶段默认验收。
平台合成模板全局，客户派生案例 tenant-private；公开发布先做明确 owner/admin 动作和脱敏审查。

| 验收场景 | 必须提供的证据 |
|---|---|
| 独立 domain/audience/cookie | preview 无法读取平台 session，bearer 不能访问平台/terminal/PG。 |
| 过期/撤销 | 网关立刻拒绝、唤醒不续期、日志 token 脱敏。 |
| 客户反馈 | 只形成 change draft，新确认/生成才改变系统。 |
| gallery 复用/撤销 | 仅复制清洗 schema/seed；没有源访谈；资源逻辑撤销。 |
| 原音/全文/摘录到期 | 无音频标记、全文不可用标记、必要证据按项目保留。 |
| 项目删除 | 即刻撤销+停止任务、异步对象清理、备份 30 天窗口及恢复删除重放。 |
| 运营故障 | 积压/lease/snapshot/预算/清理告警；访问内容授权。 |

P3 完成后才评估组织扩大使用；生产系统、真实支付/ERP、任意代码和多实例 DB 需要新的交付方案。

## 阶段评审与责任

业务负责人确认模板优先级、成功定义和预算；售前代表审查需求支持与演示价值；研发负责人确认 provider/模板/队列证据；安全与运维确认隔离、分享、保留和清理。
每个门槛记录样本/版本/环境、操作、观测结果、失败范围、证据位置及结论，不使用“应该能运行”替代记录。
发现矛盾时更新[功能](../../01-%E5%95%86%E5%8A%A1%E4%B8%8E%E9%9C%80%E6%B1%82/%E5%AE%A2%E6%88%B7%E8%B5%84%E6%96%99/functional-spec.md)、[架构](../../02-%E4%BA%A7%E5%93%81%E4%B8%8E%E5%BC%80%E5%8F%91/%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3/technical-design.md)、[契约](../../02-%E4%BA%A7%E5%93%81%E4%B8%8E%E5%BC%80%E5%8F%91/%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3/data-and-api.md)、[配置](../../../config/settings-catalog.md)和[ADR](../../02-%E4%BA%A7%E5%93%81%E4%B8%8E%E5%BC%80%E5%8F%91/%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3/0001-template-first-and-isolated-runtime.md)；本轮只完成文件审阅一致性，不运行应用测试。
