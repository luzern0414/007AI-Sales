# 方案生成（proposal-generator）

把客户的零散资料变成一份**甲方看得懂、技术上做得到、不过度承诺**的定制方案，输出 Word 审核稿和 PDF。
样板成品：`examples/`（深湾科创中心商业运营智能化方案的生成脚本）与 `examples/配图组件总览.png`。

## 目录

```
proposal-generator/
├─ SKILL.md                    本文件：工作流程与硬性规则
├─ references/                 规范（按需阅读，写之前至少读 01–05）
│  ├─ 01_信息提炼.md            从资料/会议纪要中提什么、怎么提、怎么标注来源
│  ├─ 02_文档结构.md            章节骨架、每节写什么用什么表图、完整版与汇报版
│  ├─ 03_写作规范.md            语言口径、称呼、数字、不承诺清单、技术可行性核查
│  ├─ 04_排版规范.md            页面、字体字号、表格、图题表题、分页规则
│  ├─ 05_配图规范.md            配色、图内字号、11 种图型的用法与文字长度限制
│  └─ 06_交付自检.md            内容 / 格式 / 配图逐项检查清单
├─ templates/项目信息卡.md      信息提炼的填写模板（写正文前先填它）
├─ scripts/
│  ├─ docx_kit.py              Word 排版工具（规范已固化在代码中）
│  ├─ fig_kit.py               配图组件库（14 种图型，含汇报版的场景全景、AI 对话示意、创新点）
│  ├─ figures_template.py      配图脚本模板（复制后改数据）
│  ├─ proposal_template.py     完整版正文模板（实施方案）
│  ├─ boss_template.py         汇报版正文模板（给领导看：思路、架构、场景、创新、价值）
│  ├─ export_pdf.ps1           用 Word 更新目录并导出 PDF
│  └─ check_pdf.py             PDF 自检 + 缩略图
├─ assets/icons/               Lucide 线性图标（ISC 许可）
└─ examples/                   样板项目脚本、配图总览
```

## 环境

- Python 3.10+：`pip install python-docx playwright pymupdf`
- 配图渲染用本机 Chrome（`channel="chrome"`）；没有则 `python -m playwright install chromium`
- PDF 导出用 Microsoft Word（Windows，`export_pdf.ps1`）；没有 Word 时用 LibreOffice，但目录页码需先在 WPS/Word 中更新
- 字体：Windows 自带 黑体 / 宋体 / Times New Roman / 微软雅黑（配图用）

## 工作流程

1. **读全部资料**：docs 下的 PDF/PPT/Word/Excel/截图/会议纪要/简介逐个读完。PDF 用 `pdftotext -enc UTF-8 -layout` 或 PyMuPDF；Excel 读全部 sheet 和合并单元格；截图用图片查看。不要只看文件名。
2. **填项目信息卡**：复制 `templates/项目信息卡.md`，按 `references/01_信息提炼.md` 提炼。每条信息标来源；冲突的信息列出来；缺的信息列入“待甲方确认”。
3. **查场景、核技术**：检索行业做法和公开数据，核实关键判断（设备能力、精度、平台是否支持、行业指标）。按 `references/03_写作规范.md` 的“技术可行性核查”逐项过一遍，做不到的不写。
4. **定主线和框架**：用一句话写出方案主线（如“四类硬件采集数据 → 一个数据底座 → 一个平台 → 六项 AI 功能”），画出总体框架，确定每章对应框架的哪一层。
5. **建项目目录**（如项目还没有）：根保留导航与项目进展；`01-商务与需求` 下按需设 `客户资料`、`方案文件`，`02-产品与开发` 下按需设 `设计文档`、`开发记录`，`03-测试与交付` 下按需设 `测试验收`、`交付资料`；图片集中放 `docs/素材/`。每个主目录最多两个分组，分组内直接存文件；不属于分组的文件留在对应主目录，不新增杂项或历史版本目录。不预建空模板，原目录说明仅为历史，当前路径以 `docs/README.md` 为准。 原始资料包放 `data/docs-originals/`；另建 `data/`、`config/`、`src/`、`scripts/docs/` 等代码目录。
6. **出配图**：复制 `scripts/fig_kit.py`、`figures_template.py`、`assets/icons/` 到项目 `scripts/docs/`，改数据，渲染到 `docs/素材/`，**逐张查看**是否截断、折行。
7. **出 Word**：复制 `docx_kit.py`、`proposal_template.py`，按 `references/02_文档结构.md` 填正文，生成到 `docs/01-商务与需求/方案文件/`。
8. **自检**：`export_pdf.ps1` 导出预览 PDF → `check_pdf.py` 检查 → 逐张看缩略图 → 修正。
9. **交 Word 给用户审核**，说明：自己做的判断、需要甲方确认的事项、有意没写的内容（如报价）。**用户确认前不出正式 PDF。**
10. **用户确认后**：导出正式 PDF。如需给领导看，复制 `scripts/boss_template.py` 按领导视角单独写汇报版（思路、目标、“1+1+N”架构、应用场景、AI、创新点、价值；不写实施细节），配图用 `scenario_grid`、`chat_mock`、`innovation_grid` 等，规范见 02_文档结构.md 第 3 节；设备、功能、边界必须与完整版一致。
11. 旧版本保留在 `docs/01-商务与需求/方案文件/`，用“历史-”前缀区分，不删除；不要另建历史版本子目录。

## 硬性规则（违反任何一条都要返工）

- **一份完整方案**：不写“一期 / 二期 / 暂不纳入 / 二期展望”；做不到的直接不写，边界放到“系统能力说明”。
- **一条主线**：先给总体框架图和“各层说明（详见第几章）”表；同类内容用同一模板；新增内容同步到所有相关章节，不能只加一节。
- **不轻易承诺**：设备只写实际能输出的数据；精度以厂商书面承诺为准；第三方平台/接口写成前提；AI 不承诺文字准确率；未报价的写“需另行报价”，数量不定写“按勘察确定”；工期写“预计”并列前提。
- **AI 只做辅助**：程序算数字，AI 理解问题和起草文字，人确认和决定。
- **通俗**：写给甲方业务负责人看；术语首次出现用中文解释（如“文字识别（OCR）”）；结构相同的要点一律做成表格。
- **格式固定**：只用 黑体 / 宋体 / Times New Roman；字号、表格、配色按 04、05 规范，已固化在 `docx_kit.py`、`fig_kit.py` 中，不要另起样式。
- **不泄密**：不写账号密码；供应商成本价、报价默认不写进面向甲方的方案。
- **先 Word 后 PDF**：用户审核确认后才出正式 PDF。

## 常见坑

- Word 内置标题样式带“主题字体”，会让中文标题混用字体 → `docx_kit` 已清除，勿改回。
- python-docx 表格列宽会被 Word 均分 → 必须写表格网格宽度（`docx_kit.table` 已处理），列宽合计 16cm。
- 目录样式要用 Word 内置 ID（TOC1/TOC2），否则目录行距设置不生效 → 已处理。
- 文末表格后的空段落会被挤成空白页 → `save()` 已处理。
- Word 2007 导出 PDF 后关闭文档会崩溃 → `export_pdf.ps1` 每份文档单独启动 Word。
- PowerShell 5.1 读无 BOM 的中文 .ps1 会乱码 → 脚本须存为 UTF-8 with BOM。
- 文件名不能含 `< >`；占位符没替换完 `check_pdf.py` 会报出来。
