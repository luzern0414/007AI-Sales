# 01 信息提炼：从资料和会议纪要中提炼有效信息

目标：在写任何正文之前，把客户资料变成一张“项目信息卡”（模板见 `templates/项目信息卡.md`）。正文里的每个事实都应能在信息卡里找到来源。

## 1. 读什么

| 资料类型 | 读法 | 重点提取 |
|---|---|---|
| 项目简介 / 介绍文字 | 全文 | 规模、面积、数量、构成比例、现状问题 |
| 前期汇报 PPT/PDF | 逐页，含图中文字 | 已向甲方承诺或提出过的内容、甲方痛点、我方定位 |
| 报价清单 Excel | 全部 sheet、合并单元格、公式、备注列 | 设备型号与数量、软件模块、哪些“必选/赠送/可选”、付款与维保条款；**核对总价公式** |
| 会议纪要 | 全文，按人物和日期 | 决定了什么、谁拍板、甲方原话里的诉求、待办 |
| 截图（微信/企业微信等） | 逐张看图 | 痛点原话、领导关注点 |
| 合同 / 制度 / 表单 | 目录和关键条款 | 业务规则、审批流程、口径 |
| 现有系统清单 | — | 系统名称、供应商、能否导出、能否接口 |

PDF 中文提取乱码时，用 `pdftotext -enc UTF-8 -layout` 或 PyMuPDF；仍不行就渲染成图片看。

## 2. 提什么（信息卡的 10 个板块）

1. **甲方与项目**：全称、简称、所属集团、地点、规模、业态/业务构成及比例、现有人员和组织。
2. **现状**：现在怎么做（流程、工具、系统）、数据从哪里来、谁在做。
3. **痛点**：用甲方的话写；每条注明来源（“会议纪要 10/12，张总原话”）。
4. **目标与期望**：甲方想要什么结果；领导最关心什么（决定汇报版重点）。
5. **已有系统与数据**：系统名、供应商、数据能否导出、是否愿意对接。
6. **我方 / 供应商已提供的内容**：报价清单中的硬件、软件、服务，及其数量、价格、是否赠送；前期汇报中已提出的服务（如顾问服务、培训）。
7. **约束**：预算、工期、数据安全（国企/私有化）、施工条件、合规要求。
8. **决策人与对接人**：谁拍板、谁对接、谁使用。
9. **冲突与疑点**：资料之间不一致的地方（如面积、数量、比例对不上）——列出来，不要自己选一个。
10. **待甲方确认**：缺失但写方案必须的信息。

## 3. 提炼原则

- **只提有用的**：与方案范围无关的宣传语、愿景口号不进入信息卡。
- **保留原始数字**：面积、数量、百分比照抄并注明来源；需要计算的（如空置率=空置面积÷可租面积）写出算式。
- **区分事实、诉求、推断**：事实写来源；诉求写提出人；自己的推断标“推断”，正文中必须用“建议/预计”表述。
- **报价清单要拆开看**：哪些是标准产品功能、哪些是“新增 AI 模块”的设想、哪些写着“赠送配置服务”——这决定方案里写“配置”还是“开发”，以及哪些需另行报价。
- **能力核查从这里开始**：信息卡里每个“要做的功能”，都要在第 6 板块找到对应的产品/设备，找不到就进入“需另行报价”或“不写”。

## 4. 从信息卡到方案

| 信息卡板块 | 用在方案哪里 |
|---|---|
| 甲方与项目、现状 | 一、1.1 项目概况（概况图 + 基本情况表） |
| 痛点 | 一、1.2 主要问题与解决思路（每条问题对应一个对策和后文章节） |
| 目标与期望 | 一、1.3 建设目标；汇报版的重点 |
| 我方/供应商内容 | 二、2.2 建设清单；三～五章 |
| 已有系统与数据 | 四、数据来源；七、部署（边界和前提） |
| 约束 | 七、部署方式；八、工期前提 |
| 决策人与对接人 | 十、待甲方决定的事项（写建议决定时间） |
| 冲突与疑点、待确认 | 十、资料清单与待决定事项；交付时向用户说明 |
