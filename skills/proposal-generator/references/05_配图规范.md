# 05 配图规范

所有配图用 `scripts/fig_kit.py` 生成：HTML/CSS 设计 → Chrome 无头渲染 → PNG。组件和用法示例见
`scripts/figures_template.py`，效果见 `examples/配图组件总览.png`。不要用 matplotlib 或手画流程框代替。

## 1. 风格

- 克制、低饱和、商务：藏青 / 石板灰 / 雾蓝为主，暖金只做少量强调。
- 扁平：圆角卡片 + 细边框，无渐变、无阴影、无 3D、无插画。
- 图标：Lucide 线性图标（`assets/icons/`，ISC 许可），线宽 1.8，同一图中图标风格统一。
- 每张图只表达一件事，图内文字短，不写段落。

## 2. 配色（设计令牌）

| 名称 | 色值 | 用途 |
|---|---|---|
| 藏青 navy | #1F3A5F | 主色：标题块、核心模块、重点数字、圆形节点 |
| 石板灰 slate | #3E5C76 | 次色：分层标签、图标、指标卡顶边 |
| 雾蓝 steel | #7489A3 | 辅助：箭头、编号、次要条形 |
| 浅雾 mist | #E6ECF2 | 标签底色、重点层底色 |
| 纸白 paper | #F5F7FA | 卡片 / 底板 |
| 线条 line | #D5DDE6 | 边框、分隔线 |
| 正文 ink | #1F2933 | 主要文字 |
| 次要文字 sub | #66727F | 说明文字、表头 |
| 暖金 gold | #A8875A（底 #F7F2EA、边 #E2D3BC、字 #7A5F38） | 只用于“空置、风险、警示、人工确认”等强调 |
| 序列色 | #1F3A5F → #2F4C6E → #4A6582 → #7489A3 → #A3B3C6 → #C8D2DE | 同一图中多个类别（由深到浅，按重要性排序） |
| 等级色 | #1F3A5F（好）→ #7489A3 → #B49A72 → #8A6A4F（差） | 健康/关注/预警/高危等分级 |
| 工作线色 | #8EA1B8 调研 / #5E7896 硬件 / #1F3A5F 软件 / #B49A72 测试验收 | 甘特图 |

禁止：大红、亮绿、亮橙、紫色、彩虹配色；同一图中出现超过 1 种强调色。

## 3. 尺寸与字号

| 项目 | 规范 |
|---|---|
| 设计宽度 | 1000 px，内边距 26/28 px |
| 导出倍率 | 3 倍（约 300 dpi） |
| 插入宽度 | 15–15.5 cm |
| 字号放大系数 | 1.2（`FONT_SCALE`），保证插入 A4 后图内文字不小于约 8 磅 |
| 设计稿字号（放大前） | 大数字 34–38px；标题/模块名 16–21px；正文 15–17px；说明 13–15px；最小 12.5px |
| 字体 | 微软雅黑（图内）；数字同字体 |
| 圆角 | 卡片 10–12px，标签 20px（胶囊），小块 6–8px |

## 4. 图型与选用

| 场景 | 组件 | 数量与文字限制 |
|---|---|---|
| 项目概况、关键数字 | `kpi_overview(kpis, stack_title, stack_rows)` | 指标卡 3–4 个（图标 + 大数字 + 单位 + 一句说明 ≤ 12 字）；风险类数字用暖金；可附楼层/区域分层（每层标签 ≤ 4 个） |
| 构成、占比 | `donut_bars(data, ...)` | ≤ 6 类，降序；附一句结论 |
| 数据从哪来、到哪去 | `hub(sources, core_title, core_items, core_band, apps)` | 两侧各 4–6 项；名称 ≤ 8 字，说明 ≤ 12 字 |
| 总体框架、系统架构 | `layers(rows, side_items, gateway_text)` | 4–6 层，自上而下“使用端 → … → 硬件层”；每层 ≤ 7 个模块、每个 ≤ 5 字；重点层（如 AI）设为深色 |
| 业务流程（多条并列） | `lanes(rows)` | 3–7 条，每条 4–6 步，步骤名 ≤ 5 字；人工步骤标暖金 + 人形图标；带图例 |
| 单条关键流程 | `circle_flow(steps, notes)` | 4–6 步，步骤名 ≤ 6 字、说明 ≤ 8 字；下方注释 ≤ 3 条，警示用暖金 |
| 原则、方法论 | `principle_cards(roles, cards)` | 顶部分工条 2–3 段；卡片 3–5 张，标题 ≤ 6 字、说明 ≤ 16 字 |
| 评分、分级 | `grade(dims, levels, red_lines)` | 维度 3–5 个（权重合计 100）；等级 4 个；红线 ≤ 4 条 |
| 硬件布置、部署位置 | `zone_cards(zones, bus_text, base_title, base_sub)` | 3–5 个位置；设备名 ≤ 8 字；安全类设备用暖金 |
| 实施计划 | `gantt(tasks, weeks, streams, milestones, after)` | 任务 ≤ 12 行，名称 ≤ 10 字；工作线 ≤ 4 条；里程碑 3–4 个 |
| 方案比选 | `compare(options, recommend)` | 2–3 个方案，每个要点 ≤ 4 条，标出建议方案 |
| 应用场景全景（汇报版） | `scenario_grid(groups)` | 2–4 组，每组 2–4 个场景；场景名 ≤ 8 字、价值 ≤ 14 字 |
| AI 助手使用示意（汇报版） | `chat_mock(title, dialogs, footnote)` | 2–3 组问答，回答 ≤ 40 字并带出处；必须注明“示意图，数据为示例” |
| 创新点（汇报版） | `innovation_grid(items, cols)` | 4–8 个；名称 ≤ 10 字，传统做法 ≤ 18 字，本方案 ≤ 22 字 |

`principle_cards` 在汇报版有两种固定用法：顶部写“三个转变”、卡片写“四个融合”（建设思路）；顶部写一句话总目标、卡片写四字目标（建设目标，`highlight_role=0`）。

完整版配图 7–11 张为宜：概况、框架、硬件布置、数据流向、AI 原则、业务线、实施计划为基本配置。
汇报版配图 9–11 张：AI 赋能全景（总述）、概况、建设思路、建设目标、“1+1+N”架构、场景全景、融合画像、AI 助手示意、AI 原则、创新点、硬件布置。

## 5. 制作步骤

1. 复制 `fig_kit.py`、`figures_template.py`、`assets/icons/` 到项目 `scripts/docs/`。
2. 在 `figures.py` 中只改数据；图标名用 `assets/icons/` 里已有的，缺的从 `https://unpkg.com/lucide-static@0.469.0/icons/<名称>.svg` 下载。
3. 运行渲染，输出到 `docs/素材/`，文件名用中文（如“系统架构.png”）。
4. **逐张打开检查**：文字是否折行或截断、格子是否挤、图例是否清楚、颜色是否克制。折行就缩短文字，不要缩小字号。
5. 正文中用 `d.image(路径, 15.5, "图题")` 插入，图前写引导语。

## 6. 新增图型

需要新图型时，在 `fig_kit.py` 中按现有组件写法新增函数：只用设计令牌中的颜色、`page()` 统一外框、字号写在 CSS 中（会自动乘放大系数），并在本文件“图型与选用”表中登记。
