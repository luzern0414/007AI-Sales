# 三类业务 Demo 模板规划

状态：**方案草案，目录内没有源码或可执行模板**。日期：2026-10-12，Asia/Shanghai。
模板是未来可构建、可调用 API、可保存数据的基础项目，不是截图或假数据页面；详见[架构](../docs/architecture/technical-design.md)和[ADR](../docs/adr/0001-template-first-and-isolated-runtime.md)。

## 统一产物与范围

生成物固定 React + TypeScript + Vite 前端、FastAPI 后端、每个 preview workspace 的独立 SQLite。主要 CRUD、筛选与状态转换通过真实 HTTP API，刷新、后端重启和快照恢复后数据一致。
建议每次 Demo ≤3 主要业务实体、≤5 页面、≤1 主流程。辅助的固定演示角色、状态枚举不是自由新增实体，仍应计入模型/检查范围；该上限是可调整政策，不是已验证生成能力。
默认合成数据；真实客户原话、联系方式、音频 URL、合同和内部凭证不进入 seed/源码。外部动作清楚显示“模拟”，不能发真实短信、付款或修改客户系统。
MVP 同 revision 的销售和分享访客共用合成 SQLite，页面告知多人修改，owner reset 需明确丢弃本轮修改。每访客独立 DB 副本以后评估。

## CRM-lite：展示跟进过程，不替代完整 CRM

| 维度 | 模板规划 |
|---|---|
| 主要实体 | 客户、商机、跟进记录，共 3 类。 |
| 页面 | 概览、客户列表/详情、商机列表、商机详情、跟进表单，共最多 5。详情用同页分区避免隐含新增屏幕。 |
| 主流程 | 新建商机 → 已联系 → 需求确认 → 演示中 → 已结束；结束结果由人工选择。 |
| 真实 API | 客户/商机/跟进 list/create/get/update/delete；按阶段筛选；合法阶段转换。 |
| 合成 seed | “样例客户甲/乙”，虚构行业/商机，无真实电话邮件，约 5–10 条。 |
| 可改部分 | 字段标签、有限自定义字段、阶段枚举、筛选、表单及主题。 |
| 不支持 | 自动成交预测、邮件/通话同步、真实 ERP/CRM、报价/合同/回款。 |

记录跟进时关联商机，删除父对象需遵循已确认的阻止/级联规则；不能产生孤儿跟进。成交/结束不是 AI 推断，演示中由用户操作。
验证路径：创建客户和商机、添加跟进、改阶段、筛选、刷新、重启读取；删除合成记录后查不到，非法阶段转换返回业务错误。

## 工单：把报修、派单与确认跑起来

| 维度 | 模板规划 |
|---|---|
| 主要实体 | 设备、工单、处理记录，共 3 类。 |
| 页面 | 概览、工单列表、工单详情、报修表单、设备列表。 |
| 主流程 | 新建 → 已分派 → 处理中 → 待确认 → 已完成；主管驳回回处理中。 |
| 真实 API | 三实体 CRUD、按状态/设备筛选、分派/提交/确认状态 API。 |
| 合成 seed | “测试冷柜 A/设备 B”，虚构故障和处理记录，不填真实员工信息。 |
| 可改部分 | 设备/故障字段、有限状态名称、优先级、表单、列表及固定角色提示。 |
| 不支持 | 真实短信/微信、地图调度、复杂排班、库存财务、多组织服务。 |

默认固定演示角色为前台、工程师、主管，可在预览切换以讲解流程，后端仍校验所选演示角色允许动作；此模式不是生产身份认证。
状态变化保留处理记录，工单未分派不能提交完成；客户可演示写入，但没有模板/runtime 管理权。
验证路径：新增报修、主管派单、工程师提交结果、主管确认、拒绝非法跳转、编辑刷新/重启、删除备用合成工单。

## 简单审批：展示一层规则和审批记录

| 维度 | 模板规划 |
|---|---|
| 主要实体 | 申请、审批记录；可选申请分类最多共 3 类。 |
| 页面 | 概览、申请列表、申请表单、申请详情、待审批列表。 |
| 主流程 | 草稿 → 待审批 → 已通过/已驳回；驳回可复制为新草稿再提交。 |
| 真实 API | 申请/记录 CRUD（记录追加权限受限）、提交/同意/驳回、状态筛选。 |
| 合成 seed | 虚构费用/采购申请、样例金额，展示字段不涉及真实财务数据。 |
| 可改部分 | 申请字段、分类、单审批角色、必要金额/数量校验、提示文本。 |
| 不支持 | 任意多级审批、并行会签、真实支付/签章、财务系统、动态脚本规则。 |

提交后核心字段锁定，审批结果有操作记录；默认一个固定审批角色。是否允许本人审批需销售在范围确认时选择，不能由 Agent 猜测。
审批记录不允许客户随意修改或删掉以伪造历史；演示数据 reset 由 owner 控制。复杂二级/条件分支需求须拆范围或后续模板。
验证路径：保存草稿、提交、审批通过/驳回、非法重复审批拒绝、重启后历史存在、CRUD 操作遵守记录约束。

## 模板不可变版本与 Agent 变更

| 资产/策略 | 固定要求 |
|---|---|
| template_version | 唯一 ID、版本、canonical hash、许可 manifest；发布后不覆盖。 |
| dependencies | 冻结前后端锁/hash，审核 allowlist，基础镜像 digest。 |
| scaffold/检查器 | 独立可信资产，Agent 不修改；模板版本升级人工评审。 |
| 允许 patch | 业务允许源码路径、中文标签/有限字段、页面、API、状态与合成 seed。 |
| 禁止 patch | 锁文件、镜像/registry、权限与网络策略、网关、平台 config、检查程序、宿主文件。 |
| 变更大小 | 文件/字节/行/实体/页面上限由模板 PoC 定义并服务器校验。 |
| 新依赖/真实集成 | 进入人工模板升级评审，不在单 job 自主安装。 |
| 输入绑定 | requirement_version/hash + demo_scope/hash + template/policy 版本，保留来源。 |

Agent 只拿选定模板和去标识需求，不拿所有销售资料。模板复用复制清洗 schema/seed，不复制旧客户的音频、会话、分享 token 或 SQLite 实际演示修改。
平台模板全局可见，本组织派生案例默认私有；公共发布需 owner/admin 明确脱敏审阅，不自动公开。

## 每个模板的质量验收

| gate | 判定标准 |
|---|---|
| 结构/供应链 | 固定 template/image/lock hash、patch 不越界、无秘密/真实客户信息。 |
| 前后端构建 | 前端类型/build；后端 import、health、契约与错误响应。 |
| CRUD | list/create/get/update/delete 实际写入 SQLite，未知 ID 和非法数据有合理错误。 |
| 持久化 | 刷新/重启读取相同；一致快照恢复；owner reset 回合成 seed。 |
| 业务约束 | 核心流程、关系/删除规则、演示角色动作及非法跳转。 |
| 手机 smoke | 手机 viewport 完成核心操作，无关键 console/network 错误。 |
| 预览/导出 | 只业务端口，产物与 DB snapshot 匹配，源码含锁/说明/报告/许可无 admin key。 |

自动修复最多 2 轮，不能修改 gate 以通过。失败保留错误摘要和 patch，不公开未验证预览。最多 15 分钟活动执行限额按 attempt 计，手动 retry 新 attempt 并计累计预算。
source bundle、hash/lock、验证报告与 SQLite snapshot 暂定 30 天；到期不可承诺恢复。正式生产需求转交独立数据库/身份/集成/安全/SLA 评审。
模板优先级由产品与售前用真实脱敏场景选择，当前三类尚未实现或运行。
